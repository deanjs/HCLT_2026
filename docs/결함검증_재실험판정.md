## 0. 한 줄 결론

**기존 실험을 다시 돌릴 필요는 없다.** 반드시 새로 돌려야 하는 것은 **2건**이고, 둘 다 전 층 스윕이
아니라 **봉우리 층 근방만** 돌리면 된다. 나머지 20여 항목은 전부 **재집계·서술 정정·코드 정리**다.

그리고 검증 과정에서 **주장을 크게 바꿔야 할 사실 하나**를 찾았다 — 통제를 빼고 보면
지금 논문 초안의 핵심 수치가 **한쪽은 과대, 한쪽은 과소**로 잘못 서술돼 있다(§2).

## 2. 새로 발견한 것 — 지금 수치 서술이 양쪽으로 틀려 있다

**여기가 이 문서에서 제일 중요한 부분이다.** step3는 통제 조건을 잘 세워 놓고도
**결과 보고에서 그 통제를 빼지 않았다.** 빼고 보면 그림이 달라진다.

### 2-1. 짝맞춤 통제로 다시 계산한 step3 (봉우리 층)

공여 3종 중 **`다른 camel`과 `다른 snake`는 문맥 구성이 완전히 같다**(둘 다 6함수·단일 표기 별도 모듈).
따라서 이 둘의 차이는 **오직 표기에서만** 온다 — 문맥 길이 교란이 소거된 짝맞춤 비교다.

| 모델 | 개입 | 같은 camel | 다른 camel | 다른 snake | **표기 순효과** |
|---|---|---|---|---|---|
| Qwen L25 | 내용만(Value) | 0.536 | 0.514 | 0.261 | **0.253** |
| | 어텐션만(Key) | 0.386 | 0.374 | 0.379 | **−0.005** |
| | 둘다(K+V) | 0.535 | 0.521 | 0.404 | **0.117** |
| DeepSeek L20 | Value | 0.200 | 0.208 | 0.083 | **0.125** |
| | Key | 0.149 | 0.149 | 0.144 | **0.004** |
| | K+V | 0.201 | 0.201 | 0.146 | **0.055** |
| Llama L15 | Value | 0.583 | 0.592 | 0.234 | **0.358** |
| | Key | 0.447 | 0.442 | 0.439 | **0.003** |
| | K+V | 0.562 | 0.558 | 0.456 | **0.102** |
| StableCode L18 | Value | 0.255 | 0.277 | 0.088 | **0.189** |
| | Key | 0.168 | 0.174 | 0.153 | **0.021** |
| | K+V | 0.244 | 0.249 | 0.168 | **0.080** |

여기서 세 가지가 한꺼번에 나온다.

**(가) Key가 나른 표기 정보는 0이다 — 주장이 강해진다.**
Key의 0.39는 **무엇을 덮든 똑같이 나온다**(camel 0.374 / snake 0.379). 즉 Key 치환의 회복은
공여 내용이 아니라 **"덮어쓰는 행위 자체의 교란"** 이다. 표기 정보를 나르는 건 Value뿐이고,
순효과 비율은 **Key/Value = −0.02 ~ 0.11**이다.

→ `docs/step5/구조적_결함.md` **A6**("step3에서 Key 기여가 작지 않아 펀치라인과 긴장")은 **틀렸다.**
통제를 빼지 않은 수치를 비교해서 생긴 착시다. 현재 `results.md`의 "내용−어텐션 = +0.15"는
**말할 수 있는 것보다 훨씬 약하게** 적혀 있다.

**(나) 그런데 "충분성" 주장은 통제를 빼면 무너진다 — 주장이 약해진다.**
현재 `docs/step3/results.md` §3 결론 2는 *"둘다 ≈ 내용만 → 내용이 충분(sufficient), 어텐션은 잉여"* 다.
원값으로는 맞다(0.535 vs 0.536). 그러나 **순효과로는 K+V가 Value의 절반 이하**다
(qwen 0.117 vs 0.253, llama 0.102 vs 0.358 — 4모델 모두 같은 방향).

**Key를 얹으면 표기 특정 효과가 오히려 깎인다.** 이건 "어텐션이 잉여"가 아니라
**"Key 치환이 신호를 훼손한다"** 는 뜻이고, §3-1의 RoPE 편향과 정확히 같은 지문이다.
→ 충분성 주장은 **현재 데이터로는 못 쓴다.** (역설적으로 step3 문서 A2가 "충분성을 주 논거로,
우열 비교를 보조로"라고 권한 것과 **반대**로 가야 한다.)

**(다) 통제를 안 뺀 수치는 전부 2~5배 부풀려져 있다.**
Value조차 0.536 → 0.253이다. 지금 논문 초안의 모든 회복률 숫자가 여기 해당한다.

### 2-2. 그래서 step5 수치도 부풀려져 있을 것이다 (통제가 없어서 확인 불가)

step3에서 "덮어쓰기 자체의 교란"이 **회복률의 절반 이상**을 차지한다는 걸 확인했는데,
**step5에는 통제 공여가 한 종류도 없다**(336개 전부 `opposite` 하나). 따라서 step5의
Qwen 0.78 같은 값에서 **얼마가 진짜 지침 전이이고 얼마가 교란인지 알 방법이 지금 없다.**

이것이 §4에서 step5 통제를 **필수 재실행**으로 올린 이유다. 감사 문서가 처음 이 항목을
"리뷰어 대비"로 적었지만, 실제로는 **우리 수치의 크기 자체가 미확정**이라는 문제다.

## 3. 편향 감사 — 어느 쪽으로 기울어 있나

핵심 질문: **"코드나 분석이 우리가 원하는 결론(내용/Value 쪽)으로 결과를 밀어주고 있나?"**
세 갈래로 나뉜다.

### 3-1. 🔴 우리 결론에 **유리한** 방향으로 기운 것 — 반드시 처리

**① Key 치환에 실린 위치 위상 왜곡 (RoPE)** — `step2 A3` · `step3 A2`

HuggingFace 구현은 **RoPE를 적용한 뒤의 Key를 캐시에 저장**한다(Value에는 위치 정보가 없다).
그런데 우리는 (ㄱ) 위치가 다른 공여 Key를 가져오고, (ㄴ) 서로 다른 위치의 Key 여러 개를 평균낸다.
회전 위상이 다른 벡터를 평균하면 상쇄되어 **어느 위치의 Key도 아닌 값**이 들어간다.
**Value에는 이 왜곡이 없다.** → K와 V가 대칭적으로 다뤄지지 않고, **편향 방향이 우리 결론과 같다.**

§2-1(나)의 "K+V가 Value보다 낮다"가 이 왜곡의 **직접적 증거**다. 리뷰어가 가장 먼저 찌를 곳이다.

**다만 "치명"은 아니다.** 기존 데이터에 반증이 두 개 있다.

- **step5는 위치 어긋남이 사실상 없다.** 두 지침 프롬프트를 실제로 뽑아 비교하니
  **103번째 글자까지 완전히 동일**하고, 치환 대상 `camelCase`/`snake_case`가 **양쪽 다 정확히 103번**에서
  시작한다. 위상이 맞는 상황이다.
- 그런데도 step5에서 Key/Value = 0.14~0.42로 **가장 낮다.** 반대로 위치가 **더** 어긋나는 step3에서
  Key 원값은 **더 높다**(0.15~0.45). RoPE 가설이 예측하는 방향과 반대다.

→ **전면 재실행이 아니라 진단이 먼저다**(§4-1).

**② 회복률을 통제 없이 원값으로 보고 (§2)** — 새로 발견

step3는 통제가 있는데 안 뺐고, step5는 통제 자체가 없다. **모든 헤드라인 수치가 부풀려져 있다.**
step3는 재집계로 즉시 해결되고, step5는 통제 1종 추가가 필요하다.

**③ `attn_amplify`가 조용히 "회복률 0"을 반환** — `step2 C4` · `step4 A1`

`_score_layer_kind`는 `edit_k`/`edit_v`만 보므로 `kind="attn_amplify"`면 **아무것도 안 바꾸고**
`S_int = S_base` → `recovery = 0.0`을 저장한다. 예외도 경고도 없다.
**"어텐션을 키워도 안 돌아온다"는 우리가 원하는 그림이 미구현 코드에서 자동으로 나온다.**

**단, 오염은 없다.** 결과 840개를 전수 확인한 결과 `attn_amplify` 조건이 **하나도 없다**
(스윕이 `kinds=("key","value","key_value")`를 하드코딩해 애초에 실행될 수 없었다).
→ **기존 결과는 무사. 지뢰는 터지기 전에 제거하면 된다.**

**④ 판정불가 임계 1.0이 노트북 지역 상수** — `step2 C3` · `step4 C1` · `step5 A5`

llama는 |gap| 중앙값이 0.89라 **임계선이 분포 한가운데를 지난다**(84개 중 50개가 1.0 미만).
살아남은 표본은 "지침 레버가 있는 모델"이 아니라 **오른쪽 꼬리**다. 그리고 어떤 조건이 빠졌는지
**결과 파일에 안 남는다.** → 결론(llama 전이 0.02)은 안 뒤집히지만, **표본 선택 근거를 못 댄다.**

### 3-2. 🔵 우리 결론에 **불리한** 방향으로 기운 것 — 정직하게 적어야 함

편향이 한쪽만 있는 게 아니다. **반대 방향도 있고, 이건 우리 수치를 낮춰 잡고 있다.**

| 항목 | 출처 | 왜 불리한가 |
|---|---|---|
| **회복률 분모에 도달 불가 성분** | `step3 A1` | `S_clean`은 문맥 12개를 전부 camel로 **다시 렌더한 별도 프롬프트**다. 뒤따르는 모든 토큰 위치·표현이 재계산되는데 우리는 이름 자리만 덮는다 → 단일 층 개입이 원리적으로 도달 못 하는 변화가 분모에 들어가 **회복률이 구조적으로 과소평가** |
| **지침 치환이 첫 등장만** | `step4 F2` | `spans[0]`만 덮으므로 후보열거 문장의 `camelCase`는 원본대로 남는다 → step5 전이율 **희석** |
| **`def ` 끝 공백 토큰화** | `step4 F1` | 후보를 공백 없이 토큰화해 채점하는데 실제 생성은 `" removeDuplicates"`일 수 있다 → 실제로 안 밟는 경로에 확률을 매기는 중일 가능성 (**미검증**) |

→ 논문에는 **양쪽 편향을 같이 적는 것이 가장 안전하다.** "우리 방법은 Key를 불리하게, 회복률을
낮게 잡는다"는 서술은 방어적이면서 정직하다.

### 3-3. ✅ 편향을 의심했으나 **문제없음이 확인된 것**

직접 돌려서 확인했다. 이건 오히려 **논문에 근거로 실을 수 있는 자산**이다.

| 의심 | 검증 | 결과 |
|---|---|---|
| **봉우리 층을 Value 곡선으로 골라 Key가 손해** | Key 자기 봉우리를 따로 계산 | **4모델 모두 Key 봉우리 = Value 봉우리** (차이 0.000) — 선택 편향 없음 |
| **승자의 저주**(같은 42묶음으로 층 고르고 평가) | 분할검증(앞21→층 선택, 뒤21→평가) | 4모델 모두 봉우리 층 동일, 값도 거의 같음 (`step3 C3`이 이미 확인) |
| **층 편집→복구 누적 오염** (테스트가 없음) | 양 끝 층 회복률 확인 | L0 = −0.000~0.002, 마지막 층 = 0.002~0.081 — **누적 안 됨. 복구 루프 정상** |
| **camel/snake 어휘 불균형** | 42블록 전수 | 양 진영 각 252개, 동사·명사 50개씩 모두 등장, 평균 길이 13.69 vs 13.60 — **균형 양호** |
| **통제 공여의 문맥 길이 교란** (`step3 A3`) | `다른camel`(6함수) vs `같은camel`(12함수) | 0.514 vs 0.536 — **거의 차이 없음.** 게다가 두 통제(다른camel/다른snake)는 규격이 같아 **짝맞춤 비교가 이미 가능** → step3 A3는 **재실행 불필요** |

> **step3 A3에 대한 판정 정정.** 그 문서는 통제 공여 규격 불일치 때문에 `unrelated_*` 두 조건을
> **재실행(전체의 2/3)** 해야 한다고 적었다. 그러나 문맥 길이 효과가 0.02 수준으로 작고,
> **규격이 동일한 두 통제끼리의 짝맞춤 대비**가 데이터에 이미 있으므로 **재실행 없이 해결된다.**

## 4. 꼭 다시 돌려야 하는 것 — **2건**

> **§1 승인 절차 대상.** 아래 둘 다 승인 전에는 실행하지 않는다.
> (step1을 4모델로 채우는 건 연구자 판단에 따라 **범위에서 제외**했다 — 2모델로 충분.)

### 4-1. Key 위상 진단 → (결과에 따라) Key 조건만 봉우리 층 근방 재측정

**왜 필요한가.** §3-1①의 편향 방향이 우리 결론과 같고, §2-1(나)에서 실제 지문이 나왔다.
독립적인 감사 3편이 모두 같은 지적을 했다.

**무엇을 재나 (2단계).**

1. **진단 (필수, 모델 1개 · 몇 분).** 치환 시점에
   `‖공여 Key 평균‖ / (공여 Key 노름들의 평균)` 을 층별로 찍어 남긴다.
   - **1에 가까우면** → 위상 상쇄가 없다는 뜻. **재실행 불필요**, 진단 수치를 논문 부록에 싣고 끝.
   - **뚜렷이 작으면** → 2단계로.
2. **위상 보정 Key 재측정 (조건부).** 공여 Key에 `R(위반위치)·R(공여위치)⁻¹`를 곱해 위치 위상만
   맞춰 이식한다. **전 층 스윕이 아니라 봉우리 층 ±3층, Key/K+V만** 돌리면 된다.

**결과 해석 예고(§1).**
- 보정 후에도 Key 순효과 ≈ 0 → 주장 **확정**. 지금 결론 그대로 간다.
- 보정 후 Key 순효과가 올라감 → 주장을 **"지침 신호는 Value 특이적"(step5)** 로 좁히고,
  코드 쪽은 "Value 우위"까지만 쓴다.

### 4-2. step5 통제 공여 1종 추가 (봉우리 층 근방만)

**왜 필요한가.** §2-2 — step3에서 "덮어쓰기 자체의 교란"이 회복률의 절반 이상을 차지했는데,
step5에는 통제가 **하나도 없다.** 지금 상태로는 Qwen 0.78이 얼마나 진짜인지 **말할 수 없다.**

**무엇을 재나.** `Intervention.donor`에 값 하나만 추가하면 되고 하네스 구조는 그대로다.

- **자기 통제(최소 필수):** **같은 지침**의 지시어 KV를 평균 내 덮는다 → 전이 ≈ 0이어야 정상.
- **음성 통제(권장):** 같은 문장의 무관한 단어(`project`, `function`)를 덮는다 → 전이 ≈ 0이어야 정상.

**규모.** 84조건 × 4모델 × **봉우리 층 ±3층만** (전 층 스윕 아님).

**결과 해석 예고(§1).**
- 통제 ≈ 0 → step5 원값을 그대로 써도 된다. **주장 확정.**
- 통제가 큼 → step3처럼 **순효과(처치 − 통제)로 다시 보고**한다. 크기는 줄지만
  "Value 특이적"이라는 **질적 결론은 유지**된다(Key가 통제와 같은 값이므로).

### 4-3. 재실행이 아니라 "아직 안 한 실험" — 별개로 결정 필요

아래는 *다시* 돌리는 게 아니라 **애초에 실행되지 않은** 것들이다. 논문에서 그 주장을 할 것인지에 따라
**하거나, 계획서에서 명시적으로 철회**하면 된다.

### 5-2. 서술만 고치면 되는 것 — 연구자가 지적한 7건 전부 **맞다**

**7개 모두 코드·데이터로 확인했다. 전부 정정 대상이다.**

| # | 지적 | 검증 결과 |
|---|---|---|
| 1 | `av_norm`을 "잔차에 실제로 들어간 기여량"이라 쓰면 부정확 | ✅ **맞다.** 코드는 `Σ_j mean_h a[h,j]·‖v[h÷gs,j]‖` — 삼각부등식 **상한**이고 출력 사영 `W_O` **이전** 값이다. "구간이 기여할 수 있는 크기의 상한(방향 상쇄·사영 이전)"으로 |
| 2 | "504개 함수 이름에서 행동을 측정" 은 틀림 | ✅ **맞다.** `runner.py:181·239` 모두 `gt = GENERATION_TASKS[0]` — step3·step5의 **모든** 조건에서 채점 대상은 `removeDuplicates` vs `remove_duplicates` **한 쌍**이다. 504개는 **문맥 다양성**. 42묶음 신뢰구간은 **문맥 변주에 대한 분산**이지 측정 대상 변주가 아니다 |
| 3 | `subsequent_violation_rate`를 조건부로 쓰면 구현과 다름 | ✅ **맞다.** `sum(n != target for n in notations[1:]) / len(...)` — **첫 결과와 무관한 무조건부**다. 주석만 조건부로 적혀 있다 |
| 4 | step5의 S를 `logP(camel)−logP(snake)`로 쓰면 부호 틀림 | ✅ **맞다.** 코드는 `preference_score(logp(목표 표기), logp(반대 표기))`. 데이터로도 확인 — snake 목표 조건은 `S_base > 0`이 168개 중 148개, camel 목표 조건은 `S_base < 0`이 138개. **두 방향을 평균하므로 정의를 틀리면 재현이 안 된다** |
| 5 | stable을 방향 평균 0.89 하나로 쓰면 비대칭 은폐 | ✅ **맞다.** 재집계 결과 camel 0.45 / snake 1.32, 전이율 > 1이 **84개 중 38개** |
| 6 | "코드와 지침의 인과 층이 일치" 는 아직 강하다 | ✅ **맞다.** step3 = `positive/camel/weak` **504개 전부 한 방향**, step5 = camel 168 + snake 168 **양방향 평균**. 조건 집합이 다른 두 봉우리를 맞댄 것이다 |
| 7 | "부분 회복 → 신호가 여러 층에 분산" 은 확정 불가 | ✅ **맞다.** `S_clean`은 문맥을 전부 camel로 **다시 렌더한 별도 프롬프트**의 점수라, 뒤따르는 토큰들의 위치·표현 변화까지 분모에 들어간다. 단일 층 개입은 거기 도달할 수 없다. **미달분 중 얼마가 "층이 여러 개라서"이고 얼마가 "분모가 부풀어서"인지 현재 구분 불가** |

추가로 정정해야 할 것: **표기 배정 서술**(`step2 A1`) — "같은 이름을 표기만 바꿔 비교"가 아니라
**"표기별로 짝지어진 서로 다른 이름 504개(어휘 수준 균형)"** 다. `conditions.py`의 `pool_block` 주석
("seed는 표기·위치 변주")도 사실과 다르므로 함께 고친다.
