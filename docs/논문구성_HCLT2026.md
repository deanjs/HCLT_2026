## 0. 한 문장 요약과 기여

**한 문장:** 코드 생성 모델이 표기 규약 지침을 어기는 것은 지침을 **덜 봐서가 아니라**,
문맥의 표기 신호와 지침의 영향력이 모두 **어텐션이 아닌 내용(Value)** 통로를 타고
**후반 특정 층**에 모이기 때문이며, 그 층의 내용을 밀면 준수가 되살아나지만
어텐션을 키우는 기존 접근은 실패한다. (모든 인과 주장은 **평균 덮어쓰기 KV 개입 규격**에서의 결과다 — §3-2)

**기여 3가지** (서론 마지막 단락에 그대로 들어간다)

| | 기여 | 근거 스텝 |
|---|---|---|
| **C1** | 문맥의 규약 위반이 준수율을 무너뜨리며, 완만한 하락이 아니라 **임계**임을 보인다 | step1 |
| **C2** | **통제를 뺀 순효과**로, 표기 신호와 지침 영향력이 모두 Key가 아닌 **Value**에 실리고 **후반 단일 층**에 국소화됨을 인과적으로 특정한다 | step2·3·4·5 |
| **C3** | 그 발견에서 동기를 얻은 **잔차 스트림 조향**이 어텐션 증폭보다 효과적임을 보이고, 동시에 **선호 점수 회복이 준수율을 대변하지 않음**을 밝힌다 | step6 |

C2의 "통제를 뺀"과 C3의 "점수≠준수율"이 **방법론적 기여**다. 둘 다 우리가 스스로
상한값을 발견하고 깎아낸 결과이므로, 리뷰어에게 신뢰의 근거가 된다.

### 3장. 실험 설계 (0.90쪽)

여기서 한 번에 정의하고, 4~6장은 이 정의를 재사용만 한다.

**3.1 자극** — 동사50×명사50에서 함수 이름 **504개**, 12개씩 **42묶음**.
본문·매개변수는 전 항목 동일하고 **오직 이름 표기만** 다르다(통제). 파이썬.

**3.2 모델** — 코드 특화 3(Qwen2.5-Coder-3B · DeepSeek-Coder-6.7B · StableCode-3B) + 범용 1(Llama-3.2-3B).
> 범용 1개는 대조군이지 일반화 근거가 아니다. **"코드 특화 3모델에서 일관, 범용 1모델은 달랐다"**로만 쓴다.

**3.3 측정** — 세 지표를 수식으로 정의(표1 또는 본문 수식 3개)

```
준수율        새 함수 이름이 지침 표기를 따르는 비율
선호 점수 S = logP(준수 후보) − logP(위반 후보)          교사강제, 후보 두 개 고정
되돌림 R    = (S_개입 − S_기준) / (S_깨끗 − S_기준)
```

**3.4 개입** — KV 캐시의 특정 토큰 자리를 공여 값으로 덮는다.
**Key만 / Value만 / 둘 다(결합)** 세 갈래. 조각 수가 모델마다 달라 **평균 덮어쓰기**로 통일.
> 이 규격을 **본문에 명시**한다. 결론의 유효 범위가 여기서 정해진다(§3-2).

**3.5 통제와 순효과** ← **이 절이 논문의 방법론적 무기다. 절대 줄이지 않는다.**

> 덮어쓰기는 정보를 넣는 동시에 **원래 표현을 지운다.** 그래서 통제 없이 잰 R은 **상한**이다.
> 코드 쪽은 `무관한 snake 이름`, 지침 쪽은 `자기 자신`을 덮는 통제를 함께 돌리고,
> **처치 − 통제**만 보고한다.

**3.6 판정 불가** — `|S_깨끗 − S_기준| < 1.0`이면 분모가 잡음이라 해석하지 않는다. 임계 민감도는 5장 각주.

### 4장. 문맥 위반과 준수율 절벽 (RQ1) — 0.55쪽

**그림1** — 위반 개수(0~12) × 준수율, 지침 방향 2종.

| 주장 | 근거 |
|---|---|
| **문맥 위반은 준수율을 떨어뜨린다** | 위반 0→4에서 Qwen 1.00→0.55, StableCode 0.71→0.07 |
| **완만한 하락이 아니라 임계다** | **위반 5개에서 정확히 0.000**, 42묶음 전부. 그 아래로 회복 없음 |
| **단, 지침이 모델의 사전 선호와 어긋날 때만** | snake 지침이면 위반 12개에서도 0.88~1.00 (천장) |
| **지침 순응도와 붕괴 지점은 별개** | 위반 0에서 1.00 vs 0.71로 다른데 **붕괴 지점은 둘 다 5** |

> **정직하게 쓸 것:** snake 방향은 **판정 불가**(천장 포화)다. RQ1은 **방향 조건부**로 성립한다.
> 이걸 숨기면 리뷰어가 반드시 찾아낸다. 오히려 "사전 선호와 지침이 충돌할 때만 문맥이 힘을 갖는다"는
> **더 정확한 주장**으로 바꿔 쓰는 편이 강하다.

### 5장. 신호는 어디에 있는가 (RQ2·RQ3) — 1.65쪽 ★

#### 5.1 코드의 표기 신호 (RQ2) — 0.7쪽

관측(step2)은 **3문장으로 압축**한다: 네 모델 모두 위반(snake) 구간을 토큰당 더 참조하고,
격차 봉우리는 중후반 층이다. 다만 관측은 "더 봐서"인지 "내용이 커서"인지 못 가른다 → 인과로 넘어간다.

**그림2** — 층별 표기 순효과 곡선(Value vs Key), 대표 모델 1~2개.
**표2** — 봉우리 층에서의 순효과 4모델.

| 모델 | 봉우리 층(깊이) | Value | Key | K+V |
|---|---|---|---|---|
| Qwen2.5-Coder-3B | L25 (71%) | **0.253±0.008** | −0.005±0.001 | 0.117±0.006 |
| DeepSeek-Coder-6.7B | L20 (65%) | **0.125±0.008** | 0.004±0.002 | 0.055±0.005 |
| Llama-3.2-3B | L15 (56%) | **0.358±0.018** | 0.003±0.001 | 0.102±0.008 |
| StableCode-3B | L18 (58%) | **0.189±0.012** | 0.021±0.003 | 0.080±0.006 |

| 주장 | 근거 | 강도 |
|---|---|---|
| **신호를 나르는 것은 Value다** | 순효과 0.13~0.36, 4모델 모두 CI가 0을 넘지 않음 | 강 |
| **Key 개입의 추가 효과는 실용적으로 무시할 수준** | camel을 덮든 snake를 덮든 **원값이 같다**(0.374 vs 0.379). 순효과 −0.005~0.021 = Value의 2~11%. **CI는 0을 배제**하므로 "0"이라 쓰지 않는다 | 중강 |
| **후반 단일 층에 국소화** | 봉우리 절반 이상인 층이 모델마다 정확히 하나. 깊이 56~71% | 중강 |
| **옮겨지는 것은 이름이 아니라 표기 형태** | 같은 이름 준수판(0.536) ≈ 무관한 camel 이름(0.514) | 중 |

> **반드시 함께 쓸 것 — "어텐션은 잉여" 주장은 철회한다.**
> K+V(0.117)가 Value 단독(0.253)의 **절반 이하**다. 잉여라면 같아야 한다.
> 공여의 Key를 넣으면 그 자리를 참조하는 정도가 함께 바뀌어 제대로 넣은 내용이 덜 읽힌다
> → **어텐션과 내용은 독립적으로 더해지지 않고 상호작용한다.** 이건 약점이 아니라 **더 흥미로운 발견**이다.

### 6장. 처방 — 잔차를 밀 것인가, 어텐션을 키울 것인가 — 1.05쪽

**이 장의 논리적 지위를 첫 문단에서 못 박는다:**

> 5장이 옳다면 두 가지가 **예측**된다(따름정리가 아니라 예측이다). ① 그 층 부근의 표현을 밀면 준수가 되살아나야 한다.
> ② 지침 스팬의 **어텐션을 키우는 것은 효과가 없어야 한다.** 6장은 이 예측을 검증한다.

**6.1 두 처방** (0.3쪽)

| | 방법 | 근거 |
|---|---|---|
| **잔차 스트림 조향** (우리) | 그 층 **블록 출력(잔차)** 에 `세기 × (camel−snake 방향)` 더하기 | 5장에서 **동기를 얻은** 별도 가설(선형 방향). CAA·ITI 계열 |
| **Spotlight** (기존) | 전 층·전 헤드에서 지시어 스팬 어텐션 비중을 ψ까지 끌어올림 | 재구현 |

— 그래야 공정한 대결이다.

| Spotlight 지시어 ψ0.3 | −0.125 | −0.051 | **0.904** | 0.274 |

| 주장 | 근거 |
|---|---|
| **어텐션을 키워도 준수는 안 돌아온다** | 회복 −0.37~0.27 (코드 특화 3모델) |
| **"구현 실패"가 아니다** | 지시어 비중 **0.002 → 0.231, 100배 이상**. 16개 조건 전부 상승 |
| **값을 밀면 되살아난다** | 실제 준수율 세기 1~2에서 Qwen 1.000 · DeepSeek 0.952 · Llama 1.000 |

**6.3 점수는 준수율을 대변하지 않는다** (0.3쪽) — **방법론적 기여**

| Qwen 세기 | 점수 회복 | **실제 준수율** | 나온 이름 |
|---|---|---|---|
| 1 | 1.243 | **1.000** | `removeDuplicates` |
| 2 | 1.643 | **1.000** | `removeDuplicates` |
| **4** | **1.733** (최고) | **0.000** | `RemoveDuplicates` ← PascalCase |

> 선호 점수는 위가 막혀 있지 않다. 세게 밀수록 계속 오르지만 그 지점에서 모델은
> 이미 다른 표기로 넘어가 있다. **회복률이 1을 넘는 구간은 되살아난 것이 아니라 지나친 것이다.**
> 조향 논문이 점수 회복만으로 성공을 주장하는 관행에 대한 경고다.

### 7장. 논의·한계·결론 (0.35쪽)

**정직하게 적을 한계 5가지** — 숨기지 않는 것이 이 논문의 자산이다.

1. **범용 모델 1개뿐.** "코드 특화 3모델에서 일관"까지만 말할 수 있다. Llama는 Spotlight가 작동(0.904)한다
2. **층 특이성은 처방 단계에서 성립하지 않는다.** 교차 주입이 더 높은 경우도 많다 → 5장의 국소화는 **관측·인과 층의 성질**이지 처방의 조건이 아니다
3. **이름 한 쌍·절벽 한 지점.** 세기 격자도 성기다(1·2·4·8)
4. **StableCode 크기는 보고하지 않는다.** 방향에 따라 3배 차이(0.45 vs 1.32) — 층·방식 대비만 쓴다
5. **자기증폭 미측정.** step1은 첫 함수만 잰다

## 3-2. ★ 주장 강도 규약 — 이 표현은 쓰지 않는다

외부 검토에서 **현재 실험이 입증한 범위를 넘는 문장** 세 종류가 지적됐고, 저장소에서
확인한 결과 **타당했다.** 본문에서 왼쪽 표현을 쓰지 않는다.

| ✗ 쓰지 않는다 | ✓ 이렇게 쓴다 | 왜 |
|---|---|---|
| "Key가 나르는 표기 정보는 **0**이다" | "Key 순효과는 Value의 **2~11%로 실용적으로 무시할 수준**" | 집계 스크립트가 `0을 무나: 아니오`로 찍는다 — **신뢰구간이 0을 배제**한다 |
| "RoPE 우려는 **기각됐다**" | "**노름 붕괴** 가설은 지지되지 않았다. 방향·위상은 검증하지 않았다" | 진단은 `‖mean(K)‖ / mean‖K‖`만 잰다 |
| "native Key 경로에 표기 정보가 없다" | "**이 평균 덮어쓰기 규격에서** Key 개입의 추가 효과가 작다" | post-RoPE 캐시를 평균으로 덮은 조건만 관측 |
| "지침을 더 보므로 문제는 attention이 아니다" | "'지침을 거의 안 본다'는 설명은 성립하지 않는다" (인과 근거는 **step5**) | 합·토큰당 평균은 **서로 다른 추정 대상** |
| "**값(Value) 조향**" | "**잔차 스트림 조향**(activation steering)" | 구현은 블록 출력 전체에 더한다 — 이후 층의 Q·K·V·FFN을 모두 바꾼다 |
| "step6은 step3이 찾은 Value 방향을 민다" | "step6은 step3에서 **동기를 얻은 별도 가설**(잔차 공간의 선형 방향)" | 두 가설은 다르다 |
| "자기 통제는 정보가 안 바뀌는 항등 개입" | "자기 통제는 **평균 풀링 + 덮어쓰기 교란**을 잡는다" | `mean` 규격이라 (k₁,k₂)→(평균,평균) |
| "후보열거는 **완전 대칭**" | "**역할 대칭**" | 토큰 수가 DeepSeek 3:4, StableCode 2:3 |
| "‖av‖ = 실제 기여량" | "Σa‖v‖ = **상한 대리치**(상쇄 무시·W_O 이전)" | `‖Σaᵢvᵢ‖`가 아니다 |

**논문 전체에 안전한 한 문장(초록·결론에 쓸 것):**

> 평균 덮어쓰기 KV 개입이라는 특정 규격에서, Value 개입은 일관된 표기 특이 효과를 보였고
> Key 개입의 추가 효과는 실용적으로 무시할 수준이었다. 다만 post-RoPE Key의 방향·위상
> 정합성은 완전히 검증되지 않았다. step6은 이 결과에서 동기를 얻은 **별도의 잔차 스트림
> 조향** 실험이다.
