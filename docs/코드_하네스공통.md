## 1. 설계 원칙 세 가지

이 세 가지를 모르면 코드가 왜 이렇게 생겼는지 이해가 안 된다.

### 원칙 1 — 조건 객체가 실험을 규정한다

RQ마다 스크립트를 만들지 않는다. `run_rq1.py` 같은 파일은 **금지**(CLAUDE.md §7).
실험 하나 = `Condition` 객체 하나 + `mode` 문자열 하나.

```python
run(condition, handle, mode="observe")     # step2·4
run(condition, handle, mode="generate")    # step1 (개입 없음) / step3·5 (개입 있음)
run(condition, handle, mode="steer")       # step6
```

왜 이렇게 하나 — 스텝마다 스크립트가 갈라지면 **어느 코드로 어느 결과가 나왔는지**
추적이 끊긴다. 실제로 그 일이 한 번 있었고(스텝별 브랜치로 하네스가 5갈래로 분기),
그걸 되돌린 것이 지금의 통합 브랜치다.

### 원칙 2 — 모델을 아는 곳과 모르는 곳을 나눈다

| | torch 필요 | 파일 | 왜 |
|---|---|---|---|
| **모델을 아는 곳** | ✅ | `model.py` · `steer.py` | 캐시 편집·훅·forward |
| **모르는 곳** | ❌ | `conditions.py` · `prompt.py` · `naming.py` · `tasks.py` · `attention_probe.py` · `intervention.py` · `metrics.py` · `results.py` | 문자열·리스트·스칼라만 |

torch는 **지연 임포트**한다(`model.py`의 함수 안에서 `import torch`).
덕분에 GPU 없는 노트북에서도 조건 스키마 검증·슬러그·프롬프트 조립·집계가 다 돌아가고,
테스트 118개 중 대부분이 GPU 없이 통과한다.

```python
# model.py 최상단에는 torch가 없다
def chat_generate(self, ...):
    import torch          # ← 여기서 처음 임포트
```

### 원칙 3 — 조용한 실패 금지

**"효과 없음"과 "실험이 안 됨"이 같은 숫자로 저장되면 안 된다.**
이게 이 코드에서 가장 많은 줄을 차지하는 방어 로직이다.

예: 치환할 토큰 자리를 하나도 못 찾으면 `S_int == S_base` → 되돌림 0.0.
이건 "개입했지만 안 돌아왔다"와 **수치가 완전히 같다.** 그래서 예외를 던진다.

```python
# model.py:312
if n_sub == 0:
    raise ValueError("치환할 토큰 자리를 하나도 찾지 못했다 — 개입이 실제로 일어나지 않는다. ...")
```

전체 목록은 §7.

## 3. 실행 한 번의 뼈대

```
 노트북 셀 ⑤
     │  Condition(model=…, preceding=…, instruction=…, intervention=…, seed=42)
     ▼
 runner.run(condition, handle, mode=…)
     │
     ├─ prompt.py    : 지침 문장 + 선행 코드 → messages [{system}, {user}]
     ├─ model.py     : 토큰화 → forward → (관측값 | 캐시 편집 | 훅)
     ├─ *_probe/intervention.py : 순수 집계
     ▼
 Metrics(compliance_rate=…, per_layer={층: {…}}, extra={…})
     │
     ▼
 results.save_result(ResultRecord(...))  →  results/<스텝>/<슬러그>.json   (불변)
```

**노트북에는 실험 로직이 없다**(CLAUDE.md §5-6). 노트북이 하는 일은
조건 목록을 만들고 `run()`을 부르고 `save_result()`로 저장하는 것뿐이다.

## 4. `run()` 라우팅

`runner.py:75` 한 함수가 모든 스텝을 받는다.

| mode | 조건 | 가는 함수 | 스텝 | 무엇 |
|---|---|---|---|---|
| `generate` | 개입 없음 | `_run_generation` | **step1** | 생성 후 표기 측정 |
| `generate` | 개입 있음 | `_run_intervention(_sweep)` | **step3·5** | KV 치환 후 선호 점수 |
| `observe` | — | `_run_observation` | **step2·4** | 구간별 어텐션·‖v‖ 관측 |
| `intervene_generate` | — | `_run_intervention_generate` | step3 보조 | 치환 후 실제 생성 |
| `vcosine` | — | `_run_cosine_sweep` | step2 보조 | camel v ↔ snake v 방향차 |
| `kv_diagnose` | — | `_run_kv_diagnostics` | **진단 A** | 평균 덮어쓰기가 Key를 망가뜨리나 |
| `steer` | — | `_run_steer` | **step6** | 값 조향 / Spotlight |
| `steer_generate` | — | `_run_steer_generate` | step6 보조 | 조향 하에 실제 생성 |

같은 `generate` 모드가 개입 유무로 갈리는 것에 주의:

```python
# runner.py:117
if condition.intervention.kind is not InterventionKind.NONE:
    return _run_intervention(condition, handle)      # step3·5
return _run_generation(condition, handle, ...)       # step1
```

## 5. 조건 → 파일명 → 결과 경로

`Condition.slug()`(`conditions.py:315`)가 조건을 파일명으로 압축한다.
**파일명만 보고 조건을 복원할 수 있어야** 재개 로직이 성립한다.

```
qwen2p5-coder-3b__pre-c0of12-pool-syn-b0__ins-pos-camel-w__int-value-sweep-compliant__tok-mean__s42
└── 모델 ──┘  └──── 선행 코드 ─────┘  └── 지침 ──┘  └──── 개입 ────┘  └정렬┘  └시드┘
```

| 조각 | 읽는 법 |
|---|---|
| `pre-c0of12-pool-syn-b0` | 12개 중 준수 0개 · POOL 구성 · 합성 · 블록 0 |
| `ins-pos-camel-w` | 긍정형 · 목표 camelCase · 약한 어조 |
| `int-value-sweep-compliant` | Value만 · 전 층 스윕 · 공여는 같은 이름 준수판 |
| `int-key+value+key-value-L27-instr-opposite` | 세 방식 동시 · L27 · 지침 타깃 · 반대 지침 공여 |
| `tok-mean` | 평균 덮어쓰기(생략되면 `all`) |

저장 경로는 **`results/<스텝>/<슬러그>.json` 하나뿐**이다(CLAUDE.md §6).
모델별 폴더로 나누지 않는다 — 슬러그에 모델명이 이미 들어 있고, 경로가 갈리면
재개 로직(이미 있으면 건너뜀)이 통째로 멈춘다.

```python
# results.py:93
def result_path(condition, step, results_dir=RESULTS_DIR):
    return Path(results_dir) / step / f"{condition.slug()}.json"
```

**불변 규약** — 이미 있는 파일에 쓰면 예외다.

```python
# results.py:106
if path.exists() and not overwrite:
    raise FileExistsError(f"결과가 이미 존재한다(불변 규약, §6): {path}. ...")
```

이 예외가 곧 **재개 장치**이기도 하다. 노트북은 저장 전에 경로 존재를 확인해
이미 끝난 조건을 건너뛴다 — 런타임이 끊겨도 남은 것만 이어서 돌린다.

`meta`가 왜 중요한가 — **KV 캐시 레이아웃이 transformers 버전마다 다르다**(§7-③).
우리는 그 자료구조를 직접 편집하므로 버전이 바뀌면 개입 대상 자체가 달라진다.
그래서 `requirements.txt`가 버전을 고정하고, `environment_meta()`가 실제 쓴 버전을 남긴다.

`per_layer`의 키가 문자열인 것에 주의 — 집계할 때 `int(k)`로 되돌린다.

```python
per_layer = {int(k): v for k, v in d.get("per_layer", {}).items()}   # metrics.py:46
```

## 7. HuggingFace — 이 연구에 실제로 쓰는 것만

### ① 모델·토크나이저 로딩

```python
# model.py:881
config    = AutoConfig.from_pretrained(spec.name)          # 층 수·헤드 수 — 모델 안 띄우고도 읽힘
tokenizer = AutoTokenizer.from_pretrained(spec.name)
model     = AutoModelForCausalLM.from_pretrained(
    spec.name, torch_dtype=torch.float16, device_map="auto",
    attn_implementation="eager",       # ← 관측(step2·4)에는 필수
)
model.eval()
```

| 인자 | 왜 |
|---|---|
| `torch_dtype="float16"` | T4 16GB에 3B~6.7B를 올리려면 반정밀도 필수 |
| `device_map="auto"` | accelerate가 층을 GPU/CPU에 자동 배치 |
| `attn_implementation="eager"` | **`output_attentions=True`는 eager에서만 어텐션 가중치를 준다.** sdpa/flash는 `None`을 돌려준다 — 조용히 빈 값이 저장된다 |

`AutoConfig`에서 읽는 값이 GQA 계산의 근거다:

```python
# model.py:50
n_attn   = cfg.num_attention_heads                 # 질문(Q) 헤드 수
n_kv     = cfg.num_key_value_heads                 # KV 헤드 수 (없으면 = n_attn)
head_dim = getattr(cfg, "head_dim", cfg.hidden_size // n_attn)
group_size = n_attn // n_kv                        # 한 KV를 공유하는 Q 헤드 수
```

### ② `apply_chat_template` — instruct 모델의 진짜 입력

`[{"role": "system", …}, {"role": "user", …}]`를 모델이 학습한 형식의 **한 문자열**로 바꾼다.
모델마다 형식이 다르다(`<|im_start|>`, `[INST]`, …).

```python
text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
```

| 인자 | 의미 |
|---|---|
| `tokenize=False` | 문자열로 받는다 ← **우리는 항상 이것** |
| `add_generation_prompt=True` | "이제 assistant가 말할 차례" 표시를 붙인다 |

왜 `tokenize=False`인가 — 우리는 그 문자열에 교사강제 접두 `"def "`를 이어 붙이고,
**직접 토큰화하면서 `offset_mapping`을 받아야** 하기 때문이다(③).

⚠️ **함정:** chat 템플릿이 문장을 변형하는 모델이 있다(공백·개행 정규화).
그러면 지침 문장을 프롬프트에서 못 찾는다. 그래서 못 찾으면 예외를 던진다(§8).

### ③ `offset_mapping` — 문자 위치에서 토큰 인덱스로

이 연구의 **모든 측정이 여기 달려 있다.** "지침의 `camelCase`라는 단어"를 재려면
그 단어가 몇 번 토큰인지 알아야 한다.

```python
# model.py:140
enc = tok(prompt_text, return_tensors="pt",
          return_offsets_mapping=True,   # ← 토큰별 (문자시작, 문자끝)
          add_special_tokens=False)      # ← chat 템플릿이 이미 특수토큰을 넣었다
offsets = [tuple(o) for o in enc.pop("offset_mapping")[0].tolist()]
```

`add_special_tokens=False`가 중요하다 — 켜 두면 BOS가 하나 더 붙어
**모든 토큰 인덱스가 1씩 밀린다.** 조용히 어긋난 자리를 재게 된다.

문자 구간 → 토큰 인덱스 변환은 순수 함수로 분리했다(테스트 가능):

```python
# attention_probe.py:93 — 겹치면(ts < ce and te > cs) 그 토큰을 구간에 넣는다
locate_token_spans(offsets, {"instruction": [(120, 260)], …})
# → {"instruction": [31, 32, 33, …]}
```

이름이 하위토큰 여러 개로 쪼개져도 전부 잡힌다. 그게 이 연구에 필수인 이유:

```
formatMatrix   → ["format", "Matrix"]        2조각
format_matrix  → ["format", "_", "matrix"]   3조각    ← 같은 이름인데 조각 수가 다르다
```

### ④ `past_key_values` — 우리가 실제로 편집하는 물건

```python
out = model(input_ids, use_cache=True)
cache = out.past_key_values          # 층별 (Key, Value) 텐서
```

각 층의 텐서 모양은 **`[배치, KV헤드수, 토큰수, head_dim]`**.
step3·5의 개입은 이 텐서의 특정 토큰 자리를 다른 값으로 덮는 것이다.

⚠️ **레이아웃이 버전마다 다르다.** 그래서 접근을 한 곳으로 모았다:

```python
# model.py:844
def _cache_kv(cache, layer):
    if hasattr(cache, "layers"):            # transformers 4.54+
        return cache.layers[layer].keys, cache.layers[layer].values
    if hasattr(cache, "key_cache"):         # 우리가 고정한 4.46.3이 여기
        return cache.key_cache[layer], cache.value_cache[layer]
    return cache[layer][0], cache[layer][1] # 아주 옛날 tuple 형식
```

돌려주는 것은 **원본 참조**다(복사본이 아니다). 그래서 `ek[:, :, vp, :] = …`로
쓰면 캐시가 실제로 바뀐다. 이것이 개입의 핵심 메커니즘.

### ⑤ `output_hidden_states` — 잔차 스트림 꺼내기

step6이 조향 방향을 만들 때 쓴다.

```python
# steer.py:234
hs = model(input_ids, output_hidden_states=True).hidden_states[layer + 1][0]
```

⚠️ **`+1`이 필수다.** `hidden_states[0]`은 임베딩 출력(층 통과 전)이고,
`hidden_states[i+1]`이 층 `i`를 통과한 뒤다. 안 더하면 한 층 앞의 잔차를 뽑는다.

### ⑥ `register_forward_hook` — 계산 중간에 끼어들기

step6의 값 조향. 층 블록의 출력에 벡터를 더한다.

```python
# steer.py:78
def fn(_mod, _inp, out):
    self.n_calls += 1                      # ← 실제로 불렸는지 센다
    if isinstance(out, tuple):             # 디코더 블록은 튜플을 돌려준다
        hs = out[0]
        return (hs + add.to(hs.dtype).to(hs.device),) + tuple(out[1:])
    return out + add.to(out.dtype).to(out.device)

handle = layer_module.register_forward_hook(fn)
...
handle.remove()                            # ← 반드시 뗀다(컨텍스트 매니저로 보장)
```

훅을 안 떼면 **다음 측정까지 오염된다.** 그래서 `with` 블록으로 감싼다.

### ⑦ `ALL_ATTENTION_FUNCTIONS` — 어텐션 계산 자체를 갈아끼우기

Spotlight 재구현. 어텐션 가중치를 계산한 뒤 재가중해야 하므로 훅으로는 부족하고,
**어텐션 함수를 통째로 교체**한다.

```python
# steer.py:181
ALL_ATTENTION_FUNCTIONS["spotlight_step6"] = spotlight_fn
model.config._attn_implementation = "spotlight_step6"
```

⚠️ **인과 마스크를 직접 씌워야 한다.** 최신 transformers는 어텐션 함수에
`attention_mask=None`을 넘기고 인과성을 내부에서 처리한다. 그대로 두면
**미래 토큰까지 보게 되어 모델이 망가진 채로 측정된다.** 실제로 있던 버그다.

```python
# steer.py:156
else:
    q_len, k_len = attn.shape[-2], attn.shape[-1]
    causal = torch.ones(q_len, k_len, dtype=torch.bool,
                        device=attn.device).tril(diagonal=k_len - q_len)
    attn = attn.masked_fill(~causal, torch.finfo(attn.dtype).min)
```

## 8. PyTorch — 알아야 할 것

| 관용구 | 어디서 | 왜 |
|---|---|---|
| `with torch.no_grad():` | 모든 forward | 학습이 아니라 측정. 안 쓰면 그래프가 쌓여 OOM |
| `torch.manual_seed(seed)` | `chat_generate` | 재현성. 우리는 온도 0(그리디)이라 사실상 결정적 |
| `.float()` 후 `log_softmax` | 채점 | fp16에서 소프트맥스가 NaN이 될 수 있다 |
| `copy.deepcopy(cache)` | `_clone_cache` | 캐시 구조를 몰라도 버전 무관하게 안전 복제 |
| `.clone()` 백업 → 복구 | `_score_layer_kind` | 층 스윕이 하나의 캐시를 재사용한다 |
| `tensor.norm(dim=-1)` | ‖v‖ | 마지막 차원(head_dim)에 대한 L2 노름 |
| `index_select` / `index_copy` | Spotlight | 스팬 열만 골라 곱하고 되돌려 넣기 |
| `torch.einsum("bknd,bkmd->bknm", u, u)` | 진단 A | 조각쌍 코사인 행렬 한 번에 |

### 텐서 모양 규약 (이 코드에서 계속 나온다)

```
input_ids       [1, seq]                     배치는 항상 1
어텐션 가중치     [1, Hq,  seq, seq]           output_attentions
KV 캐시          [1, Hkv, seq, head_dim]      past_key_values   ← Hq가 아니라 Hkv!
잔차(hidden)     [1, seq, d_model]            output_hidden_states
```

**어텐션은 Q헤드 개, KV는 KV헤드 개**다. GQA에서 이 둘이 다르다.
곱할 때 반드시 `h // group_size`로 매핑해야 한다:

```python
# attention_probe.py:31
av_j = sum(attn_last[h][j] * vnorm_kv[h // group_size][j] for h in range(Hq)) / Hq
#                            └─ Q헤드 h → 그 그룹의 KV헤드
```

틀리면 **에러 없이 잘못된 값**이 나온다. 그래서 모양을 검사한다:

```python
# attention_probe.py:59
if group_size <= 0 or Hq != Hkv * group_size:
    raise ValueError(f"GQA 매핑 불일치: Hq={Hq}, Hkv={Hkv}, group_size={group_size}")
```
