## 1. 왜 이 실험을 하나

step2(관측)는 **답을 주지 못했다.** 처음에는 "위반 구간을 더 본다"까지 갔다고 봤지만,
표기 배치가 시드로 고정돼 있어 **"위반을 본다"와 "앞자리를 본다"가 완전히 겹쳐 있었다.**
배치를 뒤집은 시드로 다시 재자 Qwen·Llama에서 부호가 뒤집혔고, 그 서술은 철회됐다
(→ `docs/step2/results.md` §3-6).

**그래서 RQ2의 답은 전적으로 이 스텝이 진다.** 관측이 못 가른 것을 인과로 가른다.

이 스텝은 같은 교란을 받지 않는다 — **처치와 통제가 같은 자리를 건드리기 때문**이다.
문맥의 snake 이름이 어느 자리에 있든, 그 자리를 처치(준수판 camel)로도 통제(무관한 snake)로도
덮어 두 결과를 뺀다. 자리는 설계상 상수라 순효과에서 소거된다.

**RQ2(인과) — 표기 신호는 Key(얼마나 보나)에 있나 Value(무엇을 읽나)에 있나? 어느 층인가?**

논문의 핵심 주장이 여기서 나온다.

---

## 2. 무엇을 건드리나

문맥의 **위반 이름(snake) 6개**가 모델 속에 남긴 흔적을, **준수판(camel)의 것으로 바꿔치기**한다.

```
   화면의 글자:   def merge_data(items):        ← 그대로 둔다
                          │
   모델 속 캐시:  ┌────────┴────────┐
                 │  K  ←── 교체?    │  ← 어텐션만
                 │  V  ←── 교체?    │  ← 내용만
                 └─────────────────┘
```

세 가지 방식으로 나눠 건드린다.

| 방식 | 무엇을 바꾸나 | 뜻 |
|---|---|---|
| **어텐션만 (Key)** | K만 | 얼마나 볼지가 바뀐다 |
| **내용만 (Value)** | V만 | 무엇을 가져올지가 바뀐다 |
| 둘다 (K+V) | 둘 다 | |

이걸 **모든 층에서 하나씩** 반복한다(전 층 스윕).

## 2-1. 실제로 만들어지는 프롬프트 세 개

말로만 "무관한 별도 모듈"이라고 하면 안 그려진다. **아래는 실제로 모델에 들어가는 글자다**
(`runner.py:420 _preference_setup`이 만든 것을 그대로 찍었다. 재현: §2-3).

세 개가 만들어지고, **셋 중 둘만 채점한다.**

### ① 위반 프롬프트 — 실험 대상. 여기 점수를 잰다

```
[system] You are helping extend an existing Python module.
         In this project we generally write function names in camelCase.
         Every function name uses one of two styles only: camelCase or snake_case.
[user]   Here is the current module:

         ```python
         def split_config(value):     ← 위반(snake)
             return value
         def decodeNode(value): ...
         def fetchToken(value): ...
         def filter_session(value):   ← 위반
         def format_request(value):   ← 위반
         def expand_entry(value):     ← 위반
         def compute_matrix(value):   ← 위반
         def renderBuffer(value): ...
         def encodeRecord(value): ...
         def parseHeader(value): ...
         def buildPayload(value): ...
         def resolve_packet(value):   ← 위반
         ```

         Add a function that removes duplicate items from a list, preserving order.
```

지침은 camel인데 앞 코드 12개 중 **6개가 snake**. 여기서 잰 점수가 **`S_위반`(바닥)**.

### ② 깨끗한 프롬프트 — 천장 기준. 여기도 점수를 잰다

①과 **글자 하나 안 틀리고 같은데, 12개가 전부 camel**이다
(`split_config`→`splitConfig`, `filter_session`→`filterSession`, …).
여기서 잰 점수가 **`S_깨끗`(천장)**.

### ③ 공여 프롬프트 = "무관한 별도 모듈" — **채점하지 않는다**

```
[system] (①과 완전히 동일)
[user]   Here is the current module:

         ```python
         def serializeStream(value):
             return value
         def serializeBatch(value): ...
         def materializeHeader(value): ...
         def validateHandle(value): ...
         def normalizeFrame(value): ...
         def deserializeManifest(value): ...
         ```

         Add a function that removes duplicate items from a list, preserving order.
```

**함수 6개짜리 전혀 다른 코드 파일이다.** `split_config` 계열 이름은 하나도 없다
(이번 조건의 12개에 안 쓰인 이름 중에서 뽑는다 — `prompt.py:229 unrelated_specs`).
`다른 snake` 조건이면 **똑같은 6함수를 `serialize_stream`·`serialize_batch`·… 로만 바꿔** 쓴다.
`같은 camel`(처치) 조건이면 ③을 따로 만들지 않고 **②를 그대로 공여로 쓴다.**

> **③은 점수를 재지 않는다.** 오직 **내부 값을 떠오는 부품 공장**이다.
> 이 점을 놓치면 "왜 프롬프트가 세 개인지"가 끝까지 안 잡힌다.

| 프롬프트 | 함수 몇 개 | 채점하나 | 무엇을 위한 것 |
|---|---|---|---|
| ① 위반 | 12 (6개 snake) | **잰다 → `S_위반`** | 실험 대상 |
| ② 깨끗 | 12 (전부 camel) | **잰다 → `S_깨끗`** | 천장 기준 · `같은 camel` 공여로도 재사용 |
| ③ 별도 모듈 | 6 (단일 표기) | **안 잰다** | 덮어넣을 내부 값을 뽑는 곳 |

## 2-2. 측정 절차 — 층 하나당 이렇게 돈다

**점수 S 재는 법.** 프롬프트 끝에 `def `를 강제로 붙여 **이름 자리**를 만들고, 그 자리에 올
후보 두 개의 로그확률을 재서 뺀다. 후보는 새로 써 달라고 한 함수의 같은 이름 두 표기판이다.

> **S = log P(`removeDuplicates`) − log P(`remove_duplicates`)**  (nat)
> 양수 = 지침대로 쓰려는 상태 · 음수 = 위반 쪽으로 기운 상태

**절차.**

```
 준비 (딱 한 번)
   1. ①②③을 각각 한 번씩 모델에 통과시켜 캐시 3개를 만든다
   2. ①에서 잰다 → S_위반 = 0.08      (Qwen 실측)
      ②에서 잰다 → S_깨끗 = 3.69
   3. ①의 위반 이름 6개, ③의 공여 이름 6개가 각각 몇 번째 토큰인지 찾아 짝짓는다

 층 L 하나마다 (36개 층 전부, 방식 3가지씩)
   4. ③의 캐시에서 `serializeStream`이 차지한 토큰들의 값을 꺼내 평균 내 벡터 하나로 만든다
   5. ①의 캐시에서 `split_config`가 차지한 토큰 자리 **전부**에 그 벡터를 덮어쓴다.
      6개 이름 다 짝지어서. 층 L에서만. Key만/Value만/둘다 중 지정한 것만
        → 화면 글자·토큰 개수는 하나도 안 바뀐다. 바뀌는 것은 내부 값뿐이다
   6. 그 상태로 다시 잰다 → S_개입
   7. 되돌림 = (S_개입 − S_위반) / (S_깨끗 − S_위반)
   8. **원상 복구**하고 다음 층으로  ← 층 효과는 누적되지 않는다
```

평균을 내는 이유는 §3(조각 수가 달라 1:1 짝짓기가 안 된다), 되돌림 공식은 §5에 있다.

**그리고 이 전체를 ③만 갈아끼워 세 번 돌린다.** ①②는 셋 다 완전히 동일하다.

| ③에 무엇이 들어가나 | 넣는 값에 camel 정보 | Qwen L25 되돌림(내용 쪽) |
|---|---|---|
| `serializeStream`… (camel 6함수) | 있다 | 0.514 |
| `serialize_stream`… (snake 6함수) | **없다** | 0.261 |
| ②를 그대로 (같은 이름 준수판 12함수) | 있다 | 0.536 |

가운데 줄은 **camel을 하나도 안 알려주고 자리만 짓뭉갠 것**인데 0.261이 나온다. 그게 §4의 거품이다.
위 두 줄은 같은 함수 6개를 **글자 모양만 바꿔 쓴 것**이라 나머지 조건이 전부 같고,
빼면 `0.514 − 0.261 = 0.253` — 표기 때문에 생긴 몫만 남는다.

## 3. 평균 덮어쓰기 — 왜 이 방식인가

이름 하나가 토크나이저마다 다르게 쪼개진다.

```
   merge_data   →  [" merge", "_", "data"]     3조각
   mergeData    →  [" merge", "Data"]          2조각
```

조각 수가 다르면 1:1로 짝지을 수 없다. 그래서 **공여 조각들을 평균 내어 한 벡터로 만들고,
대상 이름의 모든 자리에 그 값을 넣는다.**

```
   k̄ = (1/|D|) Σ_{p ∈ D} k_p            D = 공여 조각 위치들

   대상 자리 전부 ← k̄
```

- 토크나이저와 무관 → 4모델에 같은 규격 적용
- 단어 전체를 덮으므로 신호가 강하다
- **KV 헤드 단위로 통째로** 바꾼다(GQA, 개념 문서 §4-2)

## 4. 통제 — 이 실험의 핵심 설계

**덮어쓰기는 두 가지 일을 동시에 한다.**

```
   ① 원래 있던 snake 흔적을 지운다      ← 이것만으로도 점수가 움직인다 (거품)
   ② camel 정보를 새로 넣는다           ← 우리가 알고 싶은 것
```

그래서 공여를 **세 종류**로 둔다.

| 공여 | 어디서 가져오나 | 넣는 정보 | 프롬프트 구성 |
|---|---|---|---|
| **같은 camel** (처치) | 같은 이름의 준수판 | camel | 12함수, 전부 camel |
| **다른 camel** (형태 통제) | 무관한 별도 모듈 | camel | **6함수, 단일 표기** |
| **다른 snake** (음성 통제) | 무관한 별도 모듈 | **없음** | **6함수, 단일 표기** |

**표기 순효과 = 다른 camel − 다른 snake**

두 통제는 **문맥 구성이 완전히 같다**(둘 다 6함수·단일 표기). 따라서 차이가 오직 표기에서만 온다.
문맥 길이 교란이 소거된 **짝맞춤 비교**다.

> 처치(12함수) vs 통제(6함수)의 구성 차이가 걱정되지만, `같은 camel`(0.536)과
> `다른 camel`(0.514)이 거의 같아 그 차이는 무시할 수준이다.

## 5. 재는 값

```
   S = log P(준수 이름) − log P(위반 이름)              교사강제 채점

              S_개입 − S_위반
   회복률 = ──────────────────
              S_깨끗 − S_위반

   S_깨끗 : 문맥 12개가 전부 camel인 별도 프롬프트 (천장)
   S_위반 : 실제 조건, 개입 없음 (바닥)
   S_개입 : 실제 조건에서 층 L의 K/V만 교체
```

**순효과 계산은 묶음 단위로 먼저 뺀다**(짝지음 설계).

```
   묶음 b에서:   순효과_b = 회복률(다른camel, b) − 회복률(다른snake, b)
   보고:         42묶음 평균 ± 1.96·s/√42
```
