## 2. 무엇을 건드리나

문맥의 **위반 이름(snake) 6개**가 모델 속에 남긴 흔적을, **준수판(camel)의 것으로 바꿔치기**한다.

```
   화면의 글자:   def merge_data(items):        ← 그대로 둔다
                          │
   모델 속 캐시:  ┌────────┴────────┐
                 │  K  ←── 교체?    │  ← 어텐션만
                 │  V  ←── 교체?    │  ← 내용만
                 └─────────────────┘
```

세 가지 방식으로 나눠 건드린다.

| 방식 | 무엇을 바꾸나 | 뜻 |
|---|---|---|
| **어텐션만 (Key)** | K만 | 얼마나 볼지가 바뀐다 |
| **내용만 (Value)** | V만 | 무엇을 가져올지가 바뀐다 |
| 둘다 (K+V) | 둘 다 | |

이걸 **모든 층에서 하나씩** 반복한다(전 층 스윕).

---

## 3. 평균 덮어쓰기 — 왜 이 방식인가

이름 하나가 토크나이저마다 다르게 쪼개진다.

```
   merge_data   →  [" merge", "_", "data"]     3조각
   mergeData    →  [" merge", "Data"]          2조각
```

조각 수가 다르면 1:1로 짝지을 수 없다. 그래서 **공여 조각들을 평균 내어 한 벡터로 만들고,
대상 이름의 모든 자리에 그 값을 넣는다.**

```
   k̄ = (1/|D|) Σ_{p ∈ D} k_p            D = 공여 조각 위치들

   대상 자리 전부 ← k̄
```

- 토크나이저와 무관 → 4모델에 같은 규격 적용
- 단어 전체를 덮으므로 신호가 강하다
- **KV 헤드 단위로 통째로** 바꾼다(GQA, 개념 문서 §4-2)

---

## 4. 통제 — 이 실험의 핵심 설계

**덮어쓰기는 두 가지 일을 동시에 한다.**

```
   ① 원래 있던 snake 흔적을 지운다      ← 이것만으로도 점수가 움직인다 (거품)
   ② camel 정보를 새로 넣는다           ← 우리가 알고 싶은 것
```

그래서 공여를 **세 종류**로 둔다.

| 공여 | 어디서 가져오나 | 넣는 정보 | 프롬프트 구성 |
|---|---|---|---|
| **같은 camel** (처치) | 같은 이름의 준수판 | camel | 12함수, 전부 camel |
| **다른 camel** (형태 통제) | 무관한 별도 모듈 | camel | **6함수, 단일 표기** |
| **다른 snake** (음성 통제) | 무관한 별도 모듈 | **없음** | **6함수, 단일 표기** |

**표기 순효과 = 다른 camel − 다른 snake**

두 통제는 **문맥 구성이 완전히 같다**(둘 다 6함수·단일 표기). 따라서 차이가 오직 표기에서만 온다.
문맥 길이 교란이 소거된 **짝맞춤 비교**다.

> 처치(12함수) vs 통제(6함수)의 구성 차이가 걱정되지만, `같은 camel`(0.536)과
> `다른 camel`(0.514)이 거의 같아 그 차이는 무시할 수준이다.

## 5. 재는 값

```
   S = log P(준수 이름) − log P(위반 이름)              교사강제 채점

              S_개입 − S_위반
   회복률 = ──────────────────
              S_깨끗 − S_위반

   S_깨끗 : 문맥 12개가 전부 camel인 별도 프롬프트 (천장)
   S_위반 : 실제 조건, 개입 없음 (바닥)
   S_개입 : 실제 조건에서 층 L의 K/V만 교체
```

**순효과 계산은 묶음 단위로 먼저 뺀다**(짝지음 설계).

```
   묶음 b에서:   순효과_b = 회복률(다른camel, b) − 회복률(다른snake, b)
   보고:         42묶음 평균 ± 1.96·s/√42
```

## 6. 파이프라인

```
Condition(kind=KEY_VALUE, layers="sweep", donor=..., token_unit="mean")
   │
   ▼
_preference_setup()                     위반/준수 프롬프트, 치환 대상 이름, 후보 두 개
   │
   ▼
handle.intervene_preference_sweep()
   │
   ├─ 프롬프트 3개를 forward → 캐시 확보 (위반·깨끗·공여)   ← 한 번만
   ├─ S_깨끗, S_위반 채점                                    ← 한 번만
   ├─ align_name_groups()  대상 자리 ↔ 공여 자리 묶음
   │
   └─ for 층 L:
        for 방식 in (key, value, key_value):
            ┌─ 백업 → 편집 → 채점(S_개입) → 복구 ─┐
            └─────────── 같은 캐시 재사용 ─────────┘
   │
   ▼
Metrics.per_layer[L]["value__recovery"] 등
```

**핵심 코드**

| 함수 | 파일 | 하는 일 |
|---|---|---|
| `_preference_context` | `model.py` | 캐시·후보·정렬쌍·기준 S를 한 번에 준비 |
| `_score_layer_kind` | `model.py` | **편집 → 측정 → 복구.** 이 연구의 측정 장치 |
| `align_name_groups` | `intervention.py` | 조각 수가 달라도 묶음으로 대응 |
| `recovery_rate` | `intervention.py` | 회복률 |

```python
# model.py — mean-pool 경로 (핵심)
for vps, dps in groups:                       # 이름마다
    km = dk[:, :, dps, :].mean(dim=2)         # 공여 조각들의 평균
    for vp in vps:                            # 대상 자리 전부에
        ek[:, :, vp, :] = km                  # 브로드캐스트
```

**복구가 생명이다.** 층마다 편집→측정→복구를 반복하며 **같은 캐시를 재사용**한다.
복구가 새면 앞 층의 편집이 뒤 층에 누적되어 층별 독립성이 무너진다.
→ 이걸 검사하는 테스트를 `tests/test_step3.py`에 넣었다(복구 후 비트 단위 동일).

## 10. 이 스텝의 한계

- **층 단위**까지다. 헤드·뉴런 단위 국소화는 주장하지 않는다(KV 그룹 통째로 바꿨다)
- 문맥 위반 **6/12 한 지점**
- **camel 한 방향**만(긍정형·약한 어조)
- 채점 대상은 고정된 이름 **한 쌍** — 42묶음은 문맥 다양성이지 측정 대상 다양성이 아니다
- 회복률 분모에 도달 불가 성분이 포함된다(위 §9)
