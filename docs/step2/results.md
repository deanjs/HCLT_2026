# step 2 종합 — RQ2 모델 다양성 (4모델)

**대응 RQ:** RQ2 — step1(Qwen)에서 확인한 "표기 형태 신호 = **후반 단일 층 · Value 경로 · 형태(내용 무관)**"가 한 모델의 특성이 아니라 **패밀리 간 일반 원리**인가.

**대상.** Qwen2.5-Coder-3B(step1 원본) + 패밀리가 다른 코드 instruct 3종: deepseek-coder-6.7b, stable-code-instruct-3b, granite-3b-code-instruct-2k. 데이터셋·조건은 step1과 동일(POOL n=0, pos-camel-weak, seed 0–9). 모델별 상세: `docs/step2/<model>/results.md`.

> **한 줄 결론:** **후반 단일 층 Value 경로 · 형태 신호가 4모델 모두에서 성립**한다(피크 상대 위치 0.58–0.77). Qwen과 다른 아키텍처(MHA)·토크나이저에서도 보존되므로 GQA·Qwen 특이성이 아니다. granite는 camel 지침 미준수(snake 프라이어)로 정방향에선 negative였으나, **선호 방향(snake)으로 뒤집자 같은 기제가 재현**됐다.

## 3. granite 여정 — 막힌 지점 · 대처 · 논문 영향

step2에서 granite(및 처음엔 3모델 전부)가 두 번 막혔다. 기록해 둔다(§4: 예상과 다른 결과는 그대로 남긴다).

### 막힘 ① 토크나이저 정렬 실패 (3모델 공통)

- **증상:** deepseek·stable·granite 1차 실행이 **회복률 전 층 0**. 조사하니 `n_substituted_tokens=0`, 12이름 전부 스킵 → **KV 치환이 아예 안 일어남.**
- **원인:** step1의 치환은 위반(snake)·공여(camel) 이름의 **토큰 수가 같아야** 위치를 1:1로 맞춘다. Qwen은 우연히 둘 다 2토큰이었지만, 세 모델은 snake를 `[word][_][word]`(3토큰), camel을 `[word][Word]`(2토큰)로 쪼개 **개수 불일치 → 전부 스킵.** (KV 캐시는 위치 고정이라 개수가 다르면 대응 불가.)
- **대처 — 옵션 B(마지막 토큰만 치환):** 이름의 **마지막 토큰 하나만** 1:1 치환하는 `token_unit='last'` 축을 하네스에 추가(`align_name_tokens(mode)`, `Condition.token_unit`, 슬러그 `tok-last`, 하위호환). 토큰 수가 달라도 항상 정렬되고, 표기 차이(`header`↔`Header`)가 주로 마지막 토큰에 담긴다. 아울러 **sanity 게이트를 강화**해 `n_substituted_tokens>0`이 아니면 실행을 막았다(1차 실패의 재발 방지). 1차 무효 결과는 `*_dispose/`로 보존.
- **대안 A(2:2 이름만 선별)를 안 쓴 이유:** 2단어 이름은 첫 토큰(첫 단어)이 camel/snake 공유라 치환해도 무효 — 실효 토큰은 어차피 마지막 1개뿐. A는 이득 없이 표본만 줄인다.

### 막힘 ② granite negative (S_깨끗 < 0)

- **증상:** B로 정렬은 됐으나(12/스킵0) granite만 회복이 미미(0.12)하고 Value 우세도 흐림, `S_깨끗 −0.94`.
- **진단(`notebooks/step2_granite-diagnose.ipynb`):** **H2(마지막 토큰이 형태 토큰 아님) 기각** — granite도 마지막 이름토큰 8/8 다름(B 정상). **H1(약한 선호) 확정** — clean(선행 전부 camel + camel 지침, 제일 쉬운 조건)에서도 granite가 **snake_case를 5/5 생성.** granite-3b-**code**의 Python snake 프라이어가 지침·문맥을 압도한다.
- **대처 — 방향 뒤집기(target=snake):** 지침=snake / 선행=camel(위반)로 돌리자, granite가 선호 방향에서 **Value 피크 L24(rel 0.77)·Value>Key·형태 재현.** → granite는 "기제가 없는" 게 아니라 "프라이어가 강한" 모델. camel-target negative + snake-flip positive의 **비대칭.**

### 논문에 미치는 영향

1. **방법론적 교훈(반드시 서술):** 표현 치환(activation patching류) 실험은 **토크나이저 의존적**이다. 이름 토큰 정렬 단위를 모델별로 확인해야 하며, 순진한 전체-토큰 정렬은 조용히 실패(치환 0)할 수 있다. → 우리는 **sanity에 정렬 성공 게이트**를 두고, **마지막-토큰 치환(token_unit='last')**을 교차-모델 표준으로 채택. 한계 절과 재현성 절에 명시한다.
2. **절대 크기 비교 불가 → 패턴 비교로 한정:** last-token은 snake의 `_` 마커를 남겨 회복 **크기를 축소**한다(Qwen all-token 0.65 vs 타 모델 last-token 0.12–0.24). 따라서 주장은 **회복 절대값이 아니라 국소화·Value 우세·형태의 재현**으로 스코프한다. (Qwen도 last-token으로 재실행해 같은 잣대로 맞추는 것이 후속 과제 — step1 Q4 참조.)
3. **granite = 논지의 극단 사례이자 스코프 경계:** "표층 형태가 지배"라는 논지에서, granite는 *학습 프라이어라는 형태 신호*가 지침을 이기는 극단이다. 동시에 "우리 개입은 모델이 표기를 추적할 때 유효"라는 **적용 조건**을 드러낸다 — 프라이어에 고정된 모델엔 정방향 개입 여지가 없다. 이 비대칭은 방법론(step7) 스티어링의 **적용 범위**를 정직하게 한정하는 근거가 된다.

## 5. 결론 — 다음으로

**RQ2의 답이 모델 간 일반 원리로 확정된다:** 표기 형태 신호는 **후반 단일 층의 Value 경로**에 실리는 **형태(내용 무관)** 신호이며, 이는 Qwen을 포함한 4개 코드 instruct 패밀리(MHA·GQA)에서 보존된다.

- → **step 7(형태 인식 선택적 스티어링):** 개입 지점 = 모델별 1회 스윕으로 찾은 후반 단일 층 × Value 경로. 형태 이식값이면 충분. granite류(프라이어 고정)엔 정방향 효과가 제한됨을 적용 조건으로.
- → **step 5·6(RQ3):** 같은 형태-신호 원리가 부정형 **지침 구간**에도 적용되는지. (본 step2는 개입=선행 코드; 지침 측정은 RQ3.)
- → **후속:** ① Qwen last-token 재실행으로 크기 잣대 통일, ② stepB-스타일 관측(어텐션·instruction 평탄)의 모델 일반화, ③ v 코사인 관측 지표 재정의.
