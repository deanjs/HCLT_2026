## 1. 왜 이 실험을 하나

step1에서 "문맥이 오염되면 무너진다"를 봤다. 이제 **모델 속에서 무슨 일이 벌어지는지** 본다.

**RQ2(관측) — 코드의 표기 신호는 어디에, 어느 층에 있나?**

개입은 하지 않는다. **보기만 한다.** 인과는 step3의 몫이다.

## 2. 무엇을 관측하나

문맥에 **camel 6개 + snake 6개**를 함께 넣고, 모델이 새 이름을 쓰기 **직전 시점**에
두 무리를 각각 얼마나 참조하는지 층별로 잰다.

```
[프롬프트]  ... def splitConfig(v): ...     ← camel 구간 (6개)
            ... def merge_data(x): ...      ← snake 구간 (6개)
            ...
            "def "                          ← 여기서 멈춘다 (교사강제)
                 ▲
                 └── 이 자리의 Query 한 행만 본다
```

`"def "`를 붙여 **다음에 나올 토큰이 반드시 함수 이름**이 되게 만든다.
그 시점의 어텐션 한 줄이 "이름을 쓰려는 순간 어디를 보는가"다.

## 2-1. 실제로 만들어지는 프롬프트

위 그림은 뼈대만 보인 것이다. **실제로 모델에 들어가는 글자 전체**는 아래와 같다.
step2는 **프롬프트가 하나뿐이다** — 개입이 없으니 공여도 천장 기준도 없다.

```
[system] You are helping extend an existing Python module.
         In this project we generally write function names in camelCase.
         Every function name uses one of two styles only: camelCase or snake_case.
[user]   Here is the current module:

         ```python
         def split_config(value):      ← snake(위반)
             return value
         def decodeNode(value):        ← camel(준수)
             return value
         def fetchToken(value): ...        camel
         def filter_session(value): ...    snake
         def format_request(value): ...    snake
         def expand_entry(value): ...      snake
         def compute_matrix(value): ...    snake
         def renderBuffer(value): ...      camel
         def encodeRecord(value): ...      camel
         def parseHeader(value): ...       camel
         def buildPayload(value): ...      camel
         def resolve_packet(value): ...    snake
         ```

         Add a function that removes duplicate items from a list, preserving order.
[assistant]
def ▮        ← **여기까지 강제로 붙인다.** 이 자리에서 관측한다
```

**camel 6개 · snake 6개가 균형 배치**돼 있고, **함수 몸통은 12개가 전부 `return value`** 로
같다. 달라지는 것은 **이름 표기뿐**이다. step1의 `n_compliant=6` 조건과 같은 프롬프트이고,
차이는 뒤에 `"def "`를 붙여 **생성 대신 관측**한다는 것뿐이다.

## 2-2. 측정 절차 — forward 한 번으로 전부 꺼낸다

step1은 생성시켰고 step3·5는 값을 덮었다. **step2는 아무것도 바꾸지 않는다. 보기만 한다.**

```
   1. 위 프롬프트 뒤에 "def " 를 붙여 문자열 하나를 완성한다
        → 다음에 올 토큰이 반드시 **새 함수의 이름**이 되는 자리가 만들어진다

   2. 토큰화하면서 offset(각 토큰이 원문 몇 번째 글자인지)을 함께 받는다

   3. 이름·지침의 **글자 위치**를 offset으로 **토큰 번호**로 바꾼다 ← 구간(span) 확정
        `def <이름>(` 을 정규식으로 찾아 앞 4자("def ")와 뒤 1자("(")를 깎아
        **이름 부분만** 남긴다

   4. 모델을 **한 번** 통과시킨다 (output_attentions=True, use_cache=True)

   5. 층마다 두 가지를 꺼낸다
        · 어텐션의 **마지막 한 줄** [헤드 × 전체위치]  ← "def " 자리의 query 행
        · KV 캐시의 ‖v‖ [헤드 × 전체위치]

   6. 구간에 속한 **열만** 골라 합치고, 구간 토큰 수로 나눈다
```

**어텐션 행렬은 [전체위치 × 전체위치]지만 쓰는 것은 마지막 한 줄뿐이다** —
"이름을 쓰려는 그 순간, 모델이 앞의 어디를 보고 있나". 헤드는 평균 낸다.

**구간이 실제로 어느 토큰인가** (Qwen · 블록 0 실측. 결과 파일의 `extra.token_detail`에
그대로 저장돼 있다):

| 구간 | 잡히는 토큰 (번호: 글자) | 토큰 수 |
|---|---|---|
| `code_camel` | 64:` decode` 65:`Node` · 73:` fetch` 74:`Token` · 118:` render` 119:`Buffer` · 127:` encode` 128:`Record` · 136:` parse` 137:`Header` · 145:` b`… | 12 |
| `code_snake` | `split_config`·`filter_session`… 6개 이름의 조각 전부 | 12 |
| `instruction` | system 문장 전체 | 37 |
| `instr_target_word` | `camelCase` — **2회 등장**(규칙문+후보열거) | 4 |
| `instr_viol_word` | `snake_case` — 1회(후보열거만) | 2 |

전체 길이 `seq_len`은 185토큰. 즉 **185칸 중 12칸이 camel 이름, 12칸이 snake 이름**이고,
나머지는 `def`·괄호·본문·과제 문장 등이다.

> **`def`·`(`·`value`·본문은 전부 제외한다.** `def split_config(value):`에서
> `split_config`만 잡는다. 이름이 조각 몇 개로 쪼개지든 **전부** 잡으므로,
> 밑줄을 독립 토큰으로 떼는 모델에서는 snake 구간이 길어진다 → 그래서 §4의 정규화가 필요하다.

**꺼낸 값 세 가지**는 §3의 수식대로 계산한다. 실제로 나온 값(Qwen L25, 토큰당 아님 · 구간 합):

| | `code_camel` | `code_snake` |
|---|---|---|
| 어텐션 | 0.1144 | **0.1601** |
| ‖a·v‖ | 1.029 | **1.405** |
| ‖v‖ | 9.145 | 8.988 |

어텐션 한 줄은 softmax라 **전체가 1로 합해진다.** 그래서 `0.1601`은
"이름을 쓰려는 순간 주의의 **16%** 가 snake 이름 토큰들에 갔다"는 뜻이다.

**조건 수.** 모델 4개 × 42묶음 = 168개. 시드 42, 개입 없음.

## 3. 재는 값 — 수식

층마다, 마지막 Query 행에서:

```
   a_j   = (1/H) Σ_h  a[h, j]                     어텐션 (Q 헤드 평균)
   av_j  = (1/H) Σ_h  a[h, j] · ‖v[h÷g, j]‖       기여 크기의 상한
   v_j   = (1/H_kv) Σ_k ‖v[k, j]‖                 내용 자체의 크기

   구간 값 = Σ_{j ∈ 구간} (위 값)                  ← 합
   토큰당  = 구간 값 / 구간 토큰 수                ← 이걸 쓴다
```

`g`는 GQA 그룹 크기 — Q 헤드 `h`가 쓰는 KV 헤드는 `h÷g`다(개념 문서 §4-2).

### ‖a·v‖는 상한이지 실제 기여량이 아니다

실제로 잔차에 더해지는 것은 `W_O · (Σ_j a_j v_j)`다. 우리가 재는 것은 `Σ_j a_j‖v_j‖`.

```
   ‖Σ_j a_j v_j‖  ≤  Σ_j a_j ‖v_j‖          (삼각부등식)
```

방향이 서로 상쇄되는 것을 무시했고, 출력 사영 `W_O`를 거치기 전이다.
→ **"이 구간이 기여할 수 있는 크기의 상한"** 으로만 서술한다.

## 6-2. 자리 통제 — 격차가 표기 때문인가 자리 때문인가

### 왜 필요했나

선행 코드 12개의 표기 배치를 **묶음이 아니라 시드**가 정한다(`prompt.py:151`).

```python
notations = [target] * p.n_compliant + [violation] * (p.n_functions - p.n_compliant)
random.Random(condition.seed).shuffle(notations)      # ← 묶음이 아니라 시드
```

그래서 **42묶음 전부 배치가 같다.** 시드 42에서는 1번 자리가 위반(snake)이고,
어텐션은 프롬프트 순서를 따라 떨어져 **1번이 나머지 평균의 2.5배**를 받는다.
"위반을 더 본다"와 "앞자리를 더 본다"가 100% 겹쳐 **관측만으로는 못 가른다.**

### 무엇을 바꿨나

**시드 하나만 바꾼다.** 모델·프롬프트·측정 절차는 전부 그대로다.

| 축 | 값 |
|---|---|
| 시드 | **42(기준) → 67(추가)** |
| 그 외 | 모두 동일 — 모델 4개 × 42묶음, `mode='observe'`, 지침 camel 고정 |
| 저장 | 같은 폴더 `results/step2_code-observe/`. **슬러그 끝의 `__s67`이 구분한다** |
| 노트북 | `notebooks/step2_position-control.ipynb` |

시드 67을 고른 이유는 **시드 42의 정확한 여집합**을 만들기 때문이다. 12자리가 전부 뒤집힌다:

```
시드 42 :  S C C S S S S C C C C S
시드 67 :  C S S C C C C S S S S C      ← 12/12 반대
```

### 왜 두 시드 평균이 자리를 지우나

어텐션을 `자리효과 f(자리) + 표기효과 g(표기)`로 쪼개면:

```
시드42 격차 = Σ_{위반 자리} f − Σ_{준수 자리} f + 6·g
시드67 격차 = Σ_{준수 자리} f − Σ_{위반 자리} f + 6·g     ← 자리 항만 부호 반대
──────────────────────────────────────────────────
두 시드 평균 =            0             + 6·g
```

여집합이므로 **자리 항이 식에서 빠진다** — 표본을 늘려 노이즈를 줄이는 것이 아니라 대수적 상쇄다.
집계는 **같은 묶음끼리 짝지어** 평균해 묶음 난이도까지 상쇄한다(`scripts/step2_position_control.py`).

### 어느 결과가 무슨 뜻인가 (실행 전 기록)

| 두 시드 평균 | 뜻 |
|---|---|
| 0을 문다 | 격차는 **자리** 때문이다 → §4-(1) 철회 |
| 0에서 떨어진다 | 자리를 지우고도 남는 **진짜 표기 효과**다 → 그 값으로 다시 쓴다 |
| 시드67이 **크게 반대 부호**로 나온다 | 측정 장치가 살아 있다는 **양성 통제**. "못 재서 0"과 "재 봤더니 0"을 가른다 |

→ 결과는 [`results.md`](results.md) §3-6. **Qwen·Llama에서 부호가 뒤집혀 §4-(1)을 철회했다.**

### ⚠️ 관측에는 eager 어텐션이 필수다

`output_attentions=True`는 **eager 구현에서만** 작동한다. sdpa/flash는 어텐션 행렬을 아예
만들지 않고 **경고만 찍고 무시**해 `per_layer`가 빈 채로 저장된다.

```python
handle = load_model(MODEL, attn_implementation='eager')   # ← 빠뜨리면 빈 결과가 저장된다
```

지금은 `model.py`가 어텐션이 안 돌아오면 예외를 던진다(조용한 실패 금지, CLAUDE.md §7).
그 방어가 붙기 전 실행분에서 **빈 `per_layer` 파일 2개**가 저장됐고 삭제했다(166/168조건).

## 7. 결과 요약

**snake − camel 격차가 가장 큰 층** (토큰당, **시드 42만**)

| 모델 | 어텐션 | ‖a·v‖ |
|---|---|---|
| Qwen | L25 +0.0022 | L33 +0.0190 |
| DeepSeek | L0 +0.0008 | L26 +0.0093 |
| Llama | L12 +0.0008 | L24 +0.0055 |
| StableCode | L15 +0.0011 | L15 +0.0080 |

전 모델·전 지표에서 부호가 양수로 보이지만, **이 값들은 자리 효과를 포함한 상한이다.**

**자리를 지운 값**(시드 42·67 두 시드 평균, 어텐션):

| 모델 | 시드42 봉우리 | 시드42 | 시드67 | **두 시드 평균** | 판정 |
|---|---|---|---|---|---|
| Qwen | L25 | +0.00217 | **−0.00207** | **+0.00003±0.00050** | **0을 문다 → 자리 효과** |
| Llama | L12 | +0.00079 | **−0.00089** | **−0.00005±0.00009** | **0을 문다 → 자리 효과** |
| DeepSeek | L0 | +0.00077 | +0.00099 | +0.00088±0.00004 | 남지만 음수 층이 2배 많음 |
| StableCode | L15 | +0.00108 | +0.00018 | +0.00063±0.00012 | 남지만 음수 층이 4배 많음 |

**‖a·v‖도 같이 무너진다. ‖v‖는 그대로다** — 자리 교란이 **어텐션 경로로** 들어온다는 증거다:

| 지표 | 어텐션 곱함 | 두 시드 평균이 남긴 비율 (Qwen · Llama · DeepSeek · StableCode) |
|---|---|---|
| 어텐션 | ○ | **1% · −6%** · 114% · 58% |
| ‖a·v‖ | ○ | **11% · 3%** · **−45%**(음수로 뒤집힘) · 60% |
| **‖v‖** | **✕** | 45%(원래 유의 안 함) · **97% · 93% · 110%** |

‖v‖는 어텐션을 곱하지 않으므로 배치를 바꿔도 값이 안 변하는 것이 맞다 —
**음성 통제 노릇을 하며 측정 장치가 제대로 작동함을 확인해 준다.**

→ **"위반을 더 본다"는 철회됐다.** 남은 격차도 후반이 아니라 **앞~중간 층**에 있고 후반은 음수다.
자세한 것은 [`results.md`](results.md) §3-6.

## 9. 이 스텝의 한계

- **인과가 아니다.** 상관 관측이다
- ‖a·v‖는 상한 — 실제 기여는 벡터 합의 노름이고 사영을 거친다
- 문맥 준수 6 / 위반 6 **한 지점**만 본다
- 이름을 쓰기 직전 **한 시점**의 Query 한 행만 본다
- **자리 통제는 코드 구간에만 걸었다.** 지침 구간은 시드 42 실행분에 규칙어·후보 스팬이 없어
  짝지을 수 없다(그 스팬은 step4 때 추가됐다). 다만 지침은 프롬프트 맨 앞 고정 위치라
  배치 교란이 애초에 없다 — 교란은 코드 예시 12개의 순서에서만 생긴다
