## 1. 왜 이 실험을 하나

step1에서 "문맥이 오염되면 무너진다"를 봤다. 이제 **모델 속에서 무슨 일이 벌어지는지** 본다.

**RQ2(관측) — 코드의 표기 신호는 어디에, 어느 층에 있나?**

개입은 하지 않는다. **보기만 한다.** 인과는 step3의 몫이다.

---

## 2. 무엇을 관측하나

문맥에 **camel 6개 + snake 6개**를 함께 넣고, 모델이 새 이름을 쓰기 **직전 시점**에
두 무리를 각각 얼마나 참조하는지 층별로 잰다.

```
[프롬프트]  ... def splitConfig(v): ...     ← camel 구간 (6개)
            ... def merge_data(x): ...      ← snake 구간 (6개)
            ...
            "def "                          ← 여기서 멈춘다 (교사강제)
                 ▲
                 └── 이 자리의 Query 한 행만 본다
```

`"def "`를 붙여 **다음에 나올 토큰이 반드시 함수 이름**이 되게 만든다.
그 시점의 어텐션 한 줄이 "이름을 쓰려는 순간 어디를 보는가"다.

---

## 3. 재는 값 — 수식

층마다, 마지막 Query 행에서:

```
   a_j   = (1/H) Σ_h  a[h, j]                     어텐션 (Q 헤드 평균)
   av_j  = (1/H) Σ_h  a[h, j] · ‖v[h÷g, j]‖       기여 크기의 상한
   v_j   = (1/H_kv) Σ_k ‖v[k, j]‖                 내용 자체의 크기

   구간 값 = Σ_{j ∈ 구간} (위 값)                  ← 합
   토큰당  = 구간 값 / 구간 토큰 수                ← 이걸 쓴다
```

`g`는 GQA 그룹 크기 — Q 헤드 `h`가 쓰는 KV 헤드는 `h÷g`다(개념 문서 §4-2).

### ‖a·v‖는 상한이지 실제 기여량이 아니다

실제로 잔차에 더해지는 것은 `W_O · (Σ_j a_j v_j)`다. 우리가 재는 것은 `Σ_j a_j‖v_j‖`.

```
   ‖Σ_j a_j v_j‖  ≤  Σ_j a_j ‖v_j‖          (삼각부등식)
```

방향이 서로 상쇄되는 것을 무시했고, 출력 사영 `W_O`를 거치기 전이다.
→ **"이 구간이 기여할 수 있는 크기의 상한"** 으로만 서술한다.

---

## 4. 왜 토큰 수로 나누나

밑줄을 독립 토큰으로 떼는 토크나이저가 있다.

```
   splitConfig    →  [" split", "Config"]          2토큰
   split_config   →  [" split", "_", "config"]     3토큰
```

| 모델 | camel 구간 | snake 구간 | 비율 |
|---|---|---|---|
| Qwen | 12.60 | 12.74 | 1.01 |
| Llama | 12.60 | 12.74 | 1.01 |
| **DeepSeek** | 16.21 | 22.45 | **1.38** |
| **StableCode** | 14.21 | 20.40 | **1.44** |

**합끼리 비교하면 토큰이 많은 쪽이 무조건 이긴다.** 그래서 토큰당 평균을 쓴다.

## 5. 파이프라인

```
Condition (개입 없음, composition=POOL)
   │
   ▼
build_preceding_code()            camel 6 + snake 6
   │
   ▼
handle.observe_generation_query(groups={code_camel: [...], code_snake: [...]})
   │
   ├─ chat 템플릿 + "def " 붙여 문자열 완성
   ├─ offset_mapping과 함께 토큰화     ← 글자 위치 ↔ 토큰 위치 대응
   ├─ find_char_spans()로 `def <name>(` 찾아 이름 부분만 구간에 넣음
   ├─ forward(output_attentions=True, use_cache=True)   ← 1회
   └─ 층마다 마지막 Query 행 + ‖v‖ 만 꺼내 span_metrics()
   │
   ▼
Metrics.per_layer[층]["code_snake__attention_weight"] 등
```

함수 단위 해설·호출 사슬·실제 코드 발췌는 **[`code.md`](code.md)** 에 있다. 여기서는 방법만 다룬다.

## 6. 결과 JSON 읽는 법

> 필드 요약만 여기 둔다. **예시 JSON 전문과 함정은 [`code.md`](code.md)**.

`results/step2_code-observe/*.json`

| 필드 | 뜻 |
|---|---|
| `metrics.per_layer["<층>"]["code_camel__attention_weight"]` | camel 구간 어텐션 **합** |
| `..."code_snake__av_norm"` | snake 구간 기여 상한 **합** |
| `..."code_*__v_norm"` | 내용 크기 **평균**(이건 이미 토큰당) |
| `extra.span_token_counts` | **구간별 토큰 수 — 정규화에 반드시 필요** |
| `extra.gqa` | `num_attention_heads`, `num_key_value_heads`, `group_size` |
| `extra.token_detail` | 토큰별 상세 (밑줄 분석용) |
| `extra.seq_len` | 프롬프트 길이 |

**집계 공식**

```python
cnt = r["metrics"]["extra"]["span_token_counts"]
격차 = (v["code_snake__attention_weight"] / cnt["code_snake"]
      - v["code_camel__attention_weight"] / cnt["code_camel"])
```

## 7. 결과 요약

**snake − camel 격차가 가장 큰 층** (토큰당)

| 모델 | 어텐션 | ‖a·v‖ |
|---|---|---|
| Qwen | L25 +0.0022 | L33 +0.0190 |
| DeepSeek | L0 +0.0008 | L26 +0.0093 |
| Llama | L12 +0.0008 | L24 +0.0055 |
| StableCode | L15 +0.0011 | L15 +0.0080 |

**전 모델·전 지표에서 부호가 양수** — 위반 구간을 더 참조하고, 격차는 **중후반 층**에서 커진다.

## 9. 이 스텝의 한계

- **인과가 아니다.** 상관 관측이다
- ‖a·v‖는 상한 — 실제 기여는 벡터 합의 노름이고 사영을 거친다
- 문맥 준수 6 / 위반 6 **한 지점**만 본다
- 이름을 쓰기 직전 **한 시점**의 Query 한 행만 본다
