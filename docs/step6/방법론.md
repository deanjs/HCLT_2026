## 1. 왜 이 실험을 하나

step1~5는 **"어디가 문제인지"** 를 밝혔다. step6은 **직접 고쳐본다.**

논문 형식은 "방법 제안 + 기존 기법 대비 비교"다.

```
   step1        문제 제기 (절벽)
   step2~5      왜 값(내용)이냐의 근거
   step6        결과 표 — Spotlight vs 우리        ← 헤드라인
```

---

## 2. 출발점 — 절벽 바닥

step1에서 준수율이 정확히 0이 되는 지점에서 시작한다.

```
   지침:      camelCase로 써라
   앞 코드:   12개 전부 snake_case (준수 0개)
   모델:      remove_duplicates  ← 지침 완전 무시
```

여기에 처방을 걸어 되살아나는 정도를 잰다.

---

## 3. 세 가지 방법

### 방법 A — 값 조향 (우리 것)

```
   ① 방향 만들기
      v = mean(camel 이름 자리의 잔차) − mean(snake 이름 자리의 잔차)
          └─ 같은 층에서, 같은 이름의 두 표기판을 각각 forward해서 뺀다

   ② 밀어 넣기
      h_L  ←  h_L + α · v            α = 세기 (1, 2, 4, 8)
```

- **정답 프롬프트가 필요 없다.** 방향 하나면 어디든 걸 수 있다 → 그래서 **처방**이다
- 기법 자체는 새로 만든 게 아니다 — 활성값 더하기 조향 [CAA(ACL 2024) · ITI(NeurIPS 2023)]
- **우리 기여는 "어느 층의 무엇을 밀어야 하는지"를 step2~5로 규명한 것**

### 방법 B — Spotlight (기존 접근, 재구현)

지침 스팬이 가져가는 어텐션 비중 ψ를 목표치까지 끌어올린다.
[Spotlight, arXiv:2505.12025] 원문 식(2)~(5)를 우리 데이터에 다시 돌린다.

```
   ψ = Σ_{j∈S} p_j                            지침 스팬의 어텐션 비중

   게이팅:  ψ ≥ ψ_target 이면 손대지 않는다        (식 3)

   아니면:  p_j ← p_j · (ψ_target/ψ)   for j∈S
            그리고 재정규화                        (식 4)

   결과:    ψ_after = ψ_target / (1 + ψ_target − ψ)   (식 5, 언더슛)
```

**목표에 정확히 도달하지 않는 것이 정상이다.** 재정규화 때문에 분모가 커지기 때문이다.

```
   분자 = ψ · (ψ_target/ψ) = ψ_target
   분모 = ψ_target + (1 − ψ)
```

### 방법 C — 무개입 (하한선)

**같은 교사강제 점수로** 잰다. 생성 경로로 새면 비교가 성립하지 않는다.

## 4. 원문에 없는 자유도 — 우리가 정하고 명시한다

Spotlight 논문이 정하지 않은 것들이다. 재현자가 알 수 있게 적어 둔다.

| 자유도 | 우리 결정 |
|---|---|
| 어느 쿼리 위치에 적용 | **전 쿼리 위치** |
| 헤드별 ψ vs 평균 ψ | **헤드별 독립** |
| 스팬 S | **두 종류를 다 돌린다** (아래) |

**스팬 두 종류를 다 돌리는 이유:** 어느 쪽이 Spotlight에 유리한지 자명하지 않다.

| 스팬 | 토큰 수 | ψ=0.1이 뜻하는 것 |
|---|---|---|
| `instruction` (지침 전체, 원문 정의) | 37~43 | 토큰당 0.25% |
| `rule_word` (규칙문 지시어만) | 3 | **토큰당 3.3%** — 훨씬 센 개입 |

`rule_word`는 step5에서 값을 바꾼 자리와 **정확히 같은 자리**라 대조가 날카롭다.
**둘 다 돌려서 "스팬 선택 탓"이라는 반론을 막는다.**

## 7. 여기서 조용히 틀리기 쉬운 곳 — 전부 막았다

### ① 인과 마스크 (실제로 있던 버그)

최신 transformers는 어텐션 함수에 **`attention_mask=None`** 을 넘기고 인과성을 내부에서 처리한다.
우리가 어텐션을 다시 계산하면서 마스크를 안 씌우면 **모델이 미래 토큰을 다 본다.**

```python
if attention_mask is not None:
    attn = attn + attention_mask[..., :k.shape[-2]]
else:
    # 없으면 직접 씌운다 — 안 그러면 모델이 망가진 채로 측정된다
    causal = torch.ones(q_len, k_len, dtype=torch.bool).tril(diagonal=k_len - q_len)
    attn = attn.masked_fill(~causal, torch.finfo(attn.dtype).min)
```

**고치기 전 그대로 돌렸으면 "Spotlight는 효과 없다"가 나왔을 것이다.**
그런데 그건 Spotlight 탓이 아니라 우리가 모델을 망가뜨린 탓이었을 것이다.
검증: ψ_target을 0에 가깝게 두면 기본 구현과 오차 **5e-08**로 일치.

### ② 개입이 실제로 걸렸는지

훅·어텐션 함수의 호출 횟수를 센다. **0이면 예외.**
"개입했는데 효과 없음"과 "개입이 안 걸림"이 같은 숫자로 남으면 안 된다.

### ③ ψ를 개입 전·후 모두 기록

**비중이 실제로 올랐음을 보여야** "구현을 못해서 진 것"이라는 반박을 막을 수 있다.

## 11. 이 스텝의 한계

- 채점 대상은 이름 **한 쌍** 고정
- **절벽 바닥 한 지점**(위반 12/12)만. 중간 지점은 안 본다
- 조향 방향을 step3와 **같은 데이터**에서 유도했다 — 독립 표본 일반화는 미확인
- 세기 격자가 성기다(1·2·4·8). 최적점이 1과 2 사이일 수 있다
- Spotlight 자유도 3가지는 우리가 정한 것이다
- StableCode 생성 경로 이상의 원인은 규명하지 않았다
