## Q1
### Zhang(2023)의 TC⁰·스노볼 계산복잡도 논의가 우리 논문에서 중요한가? (2026-08-09)

**짧은 답:** 부분적으로만. **스노볼 현상**은 인용하되, **TC⁰ 계산복잡도 인과기제**는 우리 것이 아니다.

Zhang의 주장은 두 층이다.
1. **현상** — 초기 오답이 컨텍스트에 남아 이후 생성을 구속하고, 일관성 유지하려다 오류가 연쇄(스노볼).
2. **인과** — 그 초기 오답은 문제가 본질적으로 순차적(소수판별·그래프연결성)이라 TC⁰ 한계를 넘어 한 번의 forward pass로 못 풀어 생기는 **초기 확언(initial committal)**.

우리가 쓰는 건 **1번뿐**이다. 우리 실험에서 모델이 하는 일은 **함수 이름을 camel/snake로 붙이는 것** — 계산적으로 사소하다. "문제가 너무 어려워 초기 확언한다"는 TC⁰ 스토리는 우리 자기증폭을 **설명하지 못한다**. 우리 원인은 RQ2가 답하는 **표층 형태 신호의 누적**이다. TC⁰를 우리 원인으로 끌어오면 오히려 RQ2 결론(형태)과 충돌한다.

**활용:** 버리지 말고 **대비**로 쓴다 — "Zhang의 스노볼은 계산적으로 어려운 사실 추론에서 발생한다. 우리는 같은 스노볼이 **계산적으로 사소한 표기 선택**에서도 나타남을 보인다 → 원인은 계산 난이도가 아니라 형태 신호다." 대비가 오히려 기여를 부각한다.

**연결:** RQ1·RQ3(자기증폭 인용) / 참고문헌의 Zhang 역할.

## Q2
### RQ3은 왜 "자기증폭"인가? RQ1의 자기증폭과 뭐가 다른가? 궁극 목표는 KV/attention 아니었나? (2026-08-09, 갱신 2026-08-11)

**짧은 답:** 궁극 목표(KV/attention)는 **RQ2가 본체**다. RQ3은 그 **같은 회로가 시간축으로 되먹임되는지**를 보는 확장이고, **자기증폭**이 그 대상이다.

**RQ1의 자기증폭 vs RQ3의 자기증폭**
- **RQ1** = 자기증폭이 **행동으로 실재하는가**(첫 위반 → 이후 연쇄 위반·잠금). *관측*까지.
- **RQ3** = 그 자기증폭이 **RQ2 회로(후반 층·Value)를 원인으로 타는가**. *기제·인과*.

**왜 자기증폭인가.** RQ2는 **고정된 선행 코드**의 형태 신호가 후반 층 Value로 읽혀 위반을 끌어당김을 보였다. 실제 세션에서는 모델이 **자기 출력을 다시 컨텍스트에 쌓는다** → 같은 신호가 세대를 거쳐 되먹임된다. RQ3은 이 되먹임이 같은 회로를 타는지 보여야, RQ2 회로가 **단발이 아니라 증폭기**임이 성립한다.

**세 leg.** ① 존재(headroom 판에서 자기증폭이 prior 지속과 분리돼 실재) = **step3** → ② 관측(턴 t+1이 턴 t의 자기 위반 토큰을 후반 층에서 더 읽나) = **step4** → ③ 인과(턴 t 출력 Value 치환 → 턴 t+1 회복) = **step5**.

**KV/attention은 RQ3에서도 계속.** step4·5 = RQ2의 KV/attention·Value 치환 렌즈를 **자기 출력** 구간에 그대로 적용 — 이어지는 것이지 갈라지는 게 아니다.

**왜 필요한가 — 방법론 때문.** 자기증폭 차단형 선택적 스티어링의 설계 근거: 추론 개입(RQ1) + **특정 층·Value 개입=KV/attention(RQ2)** + **고정 선행이 아니라 누적되는 자기 출력에 개입(RQ3)**. 기존 기법(Spotlight)은 정적·단발 개입이라 되먹임을 못 막는다. "자기증폭이 그 회로를 탄다"를 RQ3에서 보여야 **되먹임 차단** 개입이 정당화된다.

```
RQ1 코드 위반 → 붕괴 + 자기증폭 실재 (행동)
RQ2 매개 = 형태 신호·후반 층 Value   ← KV/attention 본체
RQ3 그 회로가 '자기 출력'으로 되먹임되나 (headroom·관측·인과)  ← 같은 렌즈, 시간축
      ↓
방법: 후반 층 Value에서 누적 자기 출력을 눌러 되먹임 차단
```

**연결:** RQ3 = step3(존재)·step4(관측)·step5(인과) / 방법론 = step6.

## Q3
### "코드의 내용이 아니라 형태"라면서, 개입(step 1)에선 왜 Value를 바꿔야 하나? 모순 아닌가? (2026-08-10)

**짧은 답:** 모순 아니다. "내용"이라는 말이 **두 뜻**으로 쓰여서 생긴 혼동이다. 축이 둘이다.

- **축 1 — 신호가 *무엇*인가:** 이름의 **의미(semantics)** vs **표기 형태(notation, camel/snake)**. → 답: **형태**.
- **축 2 — 신호가 *어느 통로*로 흐르나:** **Key**(어디를 볼지=라우팅) vs **Value**(무엇을 읽을지=운반물). → 답: **Value**.

"Value = 내용"의 '내용'은 **축 2의 "어텐션이 나르는 운반물"**이지, 축 1의 "코드 의미"가 아니다. 두 결론("신호는 형태다" + "그 신호는 Value 통로를 탄다")은 **층위가 달라 충돌하지 않는다.**

**구체 워크스루(seed 0).** 선행에 snake 12개(`format_matrix` …), 지침은 camel. baseline은 뒤가 전부 snake라 모델이 `remove_duplicates`(위반)를 쓴다. L25에서 위반 이름의 Value를 **이식값**으로 덮어쓴다.

| 이식값 | 의미 | 형태 | L25 회복률 |
|---|---|---|---|
| 같은이름-camel `formatMatrix` | 행렬 포맷 | camel | +0.648 |
| 다른이름-camel `parseHeader` | 헤더 파싱(딴 얘기) | camel | +0.640 |

- **의미가 완전히 틀린 이름을 이식해도 회복이 같다.** 만약 회복이 Value의 *의미* 때문이라면 엉뚱한 `parseHeader`는 회복이 나빠야 하는데 동일하다. → Value에 실린 것 중 결정을 뒤집는 **실효 성분은 "camel-ness"지 무슨 단어인가가 아니다.** (축 1 = 형태 재확인.)

**"Value를 바꾼다 = 코드 의미를 바꾼다"가 아니다.** 어텐션 배선 중 형태 신호가 **어느 선을 타는가**의 문제다.
- **Key만 치환** → "어디를 볼지"는 camel판처럼 바뀌지만 읽히는 V는 위반 snake 그대로 → 회복 X(−0.04).
- **Value만 치환** → 라우팅은 그대로, 읽히는 V만 camel판 → 회복 O(+0.65).
형태 신호는 **Key 선이 아니라 Value 선**에 있다. 텍스트는 `format_matrix` 그대로 두고, 모델이 L25에서 내부적으로 읽는 **형태 비트만** 바꾼 것이다.

**왜 정합적인가.** Value 벡터 안엔 의미·형태가 같이 실린다(코사인 96% 공유=의미, 4% 차=형태). Value를 통째로 갈아끼워도 의미 성분은 두 버전이 어차피 같으니 **실질적으로 바뀌는 건 형태 성분뿐**이다.

**연결:** RQ2 = step 1 결과(§1b·1c) / 방법론 = step 7(Value 경로 개입, 형태 이식값).

## Q4
### stepB에서 잰 ‖v‖·‖av‖와 step1의 회복률·코사인은 무슨 상관인가? (2026-08-10)

**짧은 답:** 같은 분해(축 A=어텐션 / 축 B=Value)를 **관측(stepB) → 인과(step1)**로 이어간 것이다. 그리고 step1의 코사인이 **‖v‖가 못 보던 것(방향)**을 채운다.

**한 토큰이 잔차에 기여하는 양 = a · v.** 크기로는 ‖av‖ = a · ‖v‖.
- **a(어텐션)** = 축 A, Key 쪽(Q·K가 정함).
- **v(Value)** = 크기 ‖v‖ + **방향** 둘로 나뉜다.

**stepB(관측)가 말한 것:** camel→snake에서 어텐션 a는 1.18배, ‖av‖도 1.18배, 역산한 **‖v‖는 1.002배(불변)**. → 관측되는 차이는 **어텐션(축 A)**에 있고, **Value의 크기 ‖v‖는 신호가 아니다.**

**stepB가 못 채운 두 구멍, step1이 메움:**

1. **‖v‖(크기)는 방향에 눈이 멀었다.** 크기가 같다고 v가 같은 게 아니다 — 크기 그대로 **방향**만 다를 수 있다. → step1 **코사인**이 답: L25에서 방향이 국소적으로 갈린다(0.96 딥). 즉 v는 camel/snake가 **크기는 같고 방향이 다르다.** ‖v‖로는 원리상 볼 수 없던 부분.
2. **‖av‖는 관측이라 인과를 못 정한다.** a와 v 중 무엇이 결정을 *일으키나*? ‖av‖(곱)로는 모른다. → step1 **K/V 치환**이 인과로 답: Key(a를 지배) 치환은 무반응, Value(v) 치환이 뒤집는다. **인과 레버는 v지 a가 아니다.**

**핵심 반전.** stepB에서 가장 큰 *관측* 차이는 어텐션(a, 축 A)이었다. 순진하게 읽으면 "신호는 어텐션이네"가 된다. 그런데 step1은 그 어텐션(Key)이 무반응이고 **Value의 방향**이 레버라고 말한다. → stepB의 어텐션 증가는 **증상**이고, 진짜 신호는 ‖v‖(크기)에도 안 잡히고 어텐션에도 안 잡히는 **v의 방향 성분**이다. 크기 지표(‖v‖·‖av‖)만 봤다면 오히려 엉뚱한 레버(어텐션)를 가리켰을 것이다.

**한 줄 종합:** ‖v‖ 불변(stepB) + 코사인 딥(step1) = "축 B는 크기가 아니라 방향". 회복률(step1) = "그 방향 v가 인과". 관측 3지표는 **필요했지만 불충분**했고, step1의 인과·방향 측정이 그것을 교정·완성한다.

**연결:** stepB(관측 §2.4) → step 1(인과·방향) → step 8(로짓 렌즈로 방향 성분의 로짓 기여 분해).
