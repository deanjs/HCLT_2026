# step A 결과 — RQ1 절벽 재현 (1차 실행)

**실행:** Qwen2.5-Coder-3B-Instruct (fp16), 100회 = n_compliant {4,3,2,1,0} × seed 20.
지침 = 긍정·목표 camelCase·약한 어조. 개입 없음. max_new_tokens=256, greedy.
결과 원본: `results/stepA/*.json` (불변, §6).

**대응 RQ:** RQ1 — 선행 코드의 위반이 이후 준수율을 낮추는가.

## 예측 (실행 전)

> 준수 예시 ≥1이면 85~90% 유지, 0개에서 ~30%로 급락(절벽). 첫 위반 시 자기증폭.

## 관측 결과

| n_compliant | 준수율(첫 함수) | 전체 위반율(3턴) | 평균 위반 턴/3 | 위반 턴 분포 [0,1,2,3] | camel/snake/other |
|---|---|---|---|---|---|
| 4 | 0.200 | 0.800 | 2.40 | [4, 0, 0, 16] | 12/48/0 |
| 3 | 0.200 | 0.800 | 2.40 | [4, 0, 0, 16] | 12/48/0 |
| 2 | 0.150 | 0.850 | 2.55 | [3, 0, 0, 17] | 9/51/0 |
| 1 | 0.050 | 0.950 | 2.85 | [1, 0, 0, 19] | 3/57/0 |
| 0 | 0.000 | 1.000 | 3.00 | [0, 0, 0, 20] | 0/60/0 |

전체 턴 표기: **snake 264 / camel 36 / other 0** (총 300턴, 100런).

## 세 가지 관측

1. **절벽·고원 없음 — 바닥(floor).** 예측한 "≥1이면 85~90%"가 안 나오고, n_compliant=4에서도 준수율 **0.200**. 전 구간이 낮고 약한 단조 하락(0.20→0.00)만 있다.
2. **위반 정도는 전부 all-or-nothing.** 위반 턴 분포가 항상 `[n, 0, 0, m]` — 한 런은 **3턴 모두 준수** 아니면 **3턴 모두 위반**이고, 1·2턴만 위반한 런은 **0건**. 첫 함수의 표기가 이후 두 함수를 통째로 잠근다.
3. **위반 깊이는 단조 증가.** 평균 위반 턴이 2.40(n=4) → 3.00(n=0). n_compliant가 줄수록 더 많이·더 자주 위반.

## 진단 — 왜 바닥인가

목표 표기(camelCase)가 **언어 관습과 충돌**하는 설정이었다. 세 요인이 snake 쪽으로 겹쳤다:

- 코드가 Python → 모델의 prior가 강하게 snake_case.
- n_compliant는 최대 4라, **모든 조건에서 선행 12개 중 다수(≥8)가 snake** → 데모도 snake 우세.
- 지침이 약한 어조("generally") → prior·데모를 못 이김.

그래서 camel이 나올 여유(headroom) 자체가 거의 없었다.

## RQ1 해석

- **절벽은 이 설정에서 재현되지 않았다.** 절벽을 보려면 준수율에 여유가 있는 판이 필요한데, camel-on-Python은 바닥이라 절벽이 생길 공간이 없다.
- **잠금(자기증폭)은 강하게 나타났다** (분포가 0/3로 이극화). 단, 바닥 구간에서는 "첫 선택 고수"와 "그냥 snake prior 지속"이 구분되지 않아, 이 데이터만으로 자기증폭을 단독 주장하긴 이르다.
- 방향성은 논지와 일치: 지침(내용)보다 **언어 관습이라는 표층 형태**를 따랐다 → "형태 신호 지배"의 예비 신호. 단 확증은 headroom 있는 설정에서.
