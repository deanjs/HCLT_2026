# 진단 A 방법론 — 평균 덮어쓰기가 Key를 망가뜨리는가

> **성격:** 실험이 아니라 **방법 점검**. step3·step5가 공유하는 치환 장치를 검사한다.
> **결과:** `docs/diag/결과.md`

---

## 1. 왜 필요했나

step3·step5의 결론은 **"어텐션(Key) 경로는 표기 정보를 나르지 않는다"** 이다.
그런데 우리 방법이 **Key만 불리하게** 만들었을 가능성이 있었다.

```
   K_p = 회전(p) · (원래 키)      ← 위치가 회전 형태로 박혀 캐시에 들어간다
   V_p = (원래 값)                ← 위치 정보 없음
```

우리는 **여러 위치의 조각을 평균**낸다. 회전 방향이 엇갈리면 서로 지워져
**원래보다 짧은 벡터**가 들어간다. Value에는 이 문제가 없다.

→ 편향의 방향이 **우리 결론과 같다.** 독립 감사 문서 3편이 모두 이 지점을 지적했다.

---

## 2. 무엇을 재나

```
             ‖ (1/n) Σ_p k_p ‖
   줄어듦 = ────────────────────           1이면 손해 없음
             (1/n) Σ_p ‖k_p‖
```

**Key만 재면 판단할 수 없다.** 서로 다른 조각을 평균 내면 회전이 없어도 조금은 줄어든다.
그래서 **Value의 같은 값을 기준선으로 함께 잰다.**

| 결과 | 뜻 |
|---|---|
| Key 줄어듦 ≈ Value 줄어듦 | 회전 탓 추가 손해 없음 → **결론 확정** |
| Key 줄어듦 ≪ Value 줄어듦 | 우리가 Key를 망가뜨렸다 → 위상 보정 후 재측정 |

**함께 기록하는 것**

- 조각들 사이 평균 코사인 (방향이 얼마나 흩어졌나)
- **덮을 자리와 공여 자리의 위치 차이** (어긋날수록 회전 위상도 어긋난다)

---

## 3. 왜 가벼운가

**점수를 매기지 않는다.** 프롬프트를 몇 번 통과시켜 캐시만 얻으면, 나머지는 산수다.
전 층 스윕(층수 × 3방식 × 채점)에 비해 훨씬 싸다 — **모델 하나에 몇 분.**

```
Condition (step3·step5와 완전히 같은 입력)
   │
   ▼
run(condition, mode="kv_diagnose")
   │
   ▼
handle.kv_substitution_diagnostics()
   │
   ├─ _preference_context()          치환 경로와 **같은 함수**로 캐시·정렬 확보
   └─ for 층:  공여 조각들의 K와 V 각각에 대해 줄어듦·코사인 계산
   │
   ▼
Metrics.per_layer[층]{key_shrink, value_shrink, key_minus_value, *_piece_cosine}
```

**같은 입력을 쓰는 것이 중요하다.** 다른 조건에서 재면 진단이 무의미하다.

## 4. 결과 JSON 읽는 법

`results/diag_kv-phase/*.json` — 4모델 × 6묶음 × 3갈래 = 72개

| 필드 | 뜻 |
|---|---|
| `per_layer["<층>"]["key_shrink"]` | Key 줄어듦 (1이면 손해 없음) |
| `..."value_shrink"` | Value 줄어듦 (**기준선**) |
| `..."key_minus_value"` | 차이. **음수가 크면 Key만 손해** |
| `..."key_piece_cosine"` / `"value_piece_cosine"` | 조각들이 같은 방향을 보나 |
| `extra.position_offset_abs_mean` | 덮을 자리 ↔ 공여 자리 위치 차이(칸) |
| `extra.donor_piece_counts` / `target_piece_counts` | 조각 수 |
| `extra.intervention_target` | `code`(step3) / `instruction`(step5) |

## 5. 결과 — 우려는 기각됐다

| 모델 | 대상 | Key 줄어듦 | Value 줄어듦 | 차이 |
|---|---|---|---|---|
| Qwen | 코드 | 0.948 | 0.814 | **+0.134** |
| | 지침 | 0.963 | 0.892 | **+0.071** |
| DeepSeek | 코드 | 0.957 | 0.785 | **+0.172** |
| Llama | 코드 | 0.948 | 0.810 | **+0.138** |
| StableCode | 코드 | 0.955 | 0.785 | **+0.170** |

**Key가 오히려 덜 줄어든다.** 8개 비교 전부 양수.

**이유:** 평균 내는 대상이 **한 단어 안의 이웃한 조각 2~3개**다. 회전은 위치 차이에 비례하는데
2~3칸으로는 위상이 거의 안 벌어진다. Key 조각 코사인 0.80~0.86 vs Value 0.26~0.59.

**위치 어긋남:** Qwen·Llama는 **0칸**(camel/snake 토큰 수가 같아 뒤가 안 밀린다).
DeepSeek·StableCode는 3칸, 지침 쪽은 0.5칸.

## 6. 이 진단이 확정한 것

1. **"어텐션 경로는 표기 정보를 나르지 않는다"를 그대로 주장할 수 있다.**
   리뷰어가 가장 먼저 찌를 지점이 막혔다.

2. **"어텐션을 얹으면 신호가 깎인다"(step3 §9)도 방법의 산물이 아니다.**
   Qwen은 위치 어긋남 0칸·Key 줄어듦 0.948로 멀쩡한데도 같은 현상이 나온다.
   → 어텐션과 내용이 **상호작용한다**는 실제 현상이다.

3. **위상 보정 재측정(실험 C)은 취소.** 보정할 왜곡이 없다.
