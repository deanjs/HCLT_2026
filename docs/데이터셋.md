# 데이터셋 — step별 사용 데이터 정리

이 문서는 각 step이 어떤 데이터를 선행 코드·생성 과제로 썼는지를 정리한다.
실험 데이터는 별도 파일이 아니라 **하네스 코드가 조건 축(§CLAUDE.md §3)에 따라 생성**한다.
정의 위치: `src/harness/tasks.py`(합성 과제), `data/repo_files/`(실코드),
`src/harness/prompt.py`(선행 코드·프롬프트 조립).

---

## 1. 어떻게 구성했는가

모든 실험 프롬프트는 **선행 코드 + 생성 요청**의 두 구획으로 이뤄진다.

- **선행 코드** — 모델이 프롬프트에서 *읽기만* 하는 함수들. 표기(camel/snake)를 조작해 모델에 심는 재료.
- **생성 과제** — 모델이 *새로 작성*하는 함수. 이름 표기가 측정 대상.

데이터 설계의 핵심은 **변하는 것을 이름 표기 하나로 좁히는 통제**다.

- 선행 함수의 **본문·매개변수는 고정**하고 이름 표기(camelCase / snake_case)만 바꾼다.
  → 준수율·어텐션 차이가 "내용"이 아니라 "형태"에서 왔음을 깨끗하게 가른다.
- 표기가 구분되려면 이름은 **두 단어 이상**이어야 한다(한 단어는 camel==snake).
  → 모든 과제 이름은 두 단어로 만든다.
- 생성 과제는 선행 과제와도, 서로와도 **겹치지 않게** 한다.
  → 이름 복사(모방)를 막아 모델의 "직접 선택"만 측정한다.

선행 코드는 세 가지 **구성(composition)** 과 두 가지 **출처(source)** 로 나뉘며,
이 조합이 곧 step을 구분한다.

| 구성 (`Composition`) | 뜻 | 항목 수 |
|---|---|---|
| `CLONE` | 같은 과제 1개를 인덱스만 바꿔 12복제 (`scaleValue1`, `scale_value_1`, …) | 1종 × 12 |
| `DISTINCT` | 서로 다른 과제 12개 | 12종 |
| `POOL` | 동사×명사 이름 짝 풀(80개)에서 seed로 서로 다른 n개를 뽑음 | 80종에서 표집 |

| 출처 (`Source`) | 뜻 |
|---|---|
| `SYNTHETIC` | 하네스가 만든 합성 코드 (CLONE / DISTINCT / POOL) |
| `REPO` | 허용 라이선스 저장소에서 원문 그대로 번들한 **실제 소스 파일** |

### 직접 생성한(합성) 데이터는 어떻게 만드나

합성 선행 코드는 저장된 파일이 아니라 **매 실행 시 조건(seed 포함)으로 조립**한다.

1. **표기 배열** — 준수(target) 표기 `n_compliant`개 + 위반 표기 나머지로 표기 리스트를 만들고, `seed`로 위치를 셔플한다.
2. **함수 렌더** — 구성에 따라:
   - `CLONE` : `scale value` 과제 1개를 인덱스 1..12로 12복제, 각 자리를 표기 리스트대로 camel/snake.
   - `DISTINCT` : 고정된 12과제를 앞에서부터, 표기 리스트대로.
   - `POOL` : 동사×명사 80풀에서 `seed`로 서로 다른 12개를 표집, 표기 리스트대로.
3. **프롬프트 조립** — `system`(지침 문장) + `user`(선행 코드 + `Add a function that …` 생성 요청). 이후 턴은 생성 과제만 추가.

본문·매개변수는 고정이라 **seed를 바꾸면 표기 배치(POOL은 이름 집합까지)만 달라진다.**
→ 관측된 효과가 특정 단어의 우연이 아님을 보장한다. seed는 곧 재현 가능한 배치/표집 변주다.

### 실제 프롬프트 예시

**stepA (CLONE, 준수 2/12, 지침=camel)** — 생성 경로:

```
[system] You are helping extend an existing Python module.
         In this project we generally write function names in camelCase.
         Every function name uses one of two styles only: camelCase or snake_case.

[user]   Here is the current module:
         ```python
         def scaleValue1(value, factor):
             return value * factor
         def scale_value_2(value, factor):     ← camel/snake 위치는 seed가 셔플
             return value * factor
         ... (12개) ...
         ```
         Add a function that removes duplicate items from a list, preserving order.
```

**stepC / step1 (POOL, 전부 위반, 지침=camel)** — 개입 경로. 본문을 `return value`로 통제해 **이름 표기만 변수**로 남긴다:

```
[user]   def format_matrix(value):
             return value
         def validate_stream(value):           ← seed로 뽑은 서로 다른 12개, 본문 동일
             return value
         ... (12개) ...
```

> 지침 문장은 `strength`(weak/strong)·`form`(긍정/부정)에 따라 문구가 바뀐다(`build_instruction_text`).
> 위는 긍정·약한 어조. 부정형은 `never write … in snake_case`처럼 위반 표기 토큰을 문장에 담는다.

## 2. 어떤 데이터셋들이 있는가

### 2-1. `CLONE_TASK` — 클론 선행 (합성)

같은 일(값 × 배수)을 하는 함수 1종을 인덱스만 바꿔 12개로 복제한다. 이름 표기만 조작.
`src/harness/tasks.py`

| 항목 | 값 |
|---|---|
| 단어 | `scale`, `value` → `scaleValue{i}` / `scale_value_{i}` |
| 설명 | returns the value multiplied by a factor |
| 매개변수 | `value`, `factor` |
| 본문 | `return value * factor` |
| 렌더 수 | 12 (인덱스 1..12) |
| 예시 이름 | `scaleValue1`, `scaleValue2` (camel) / `scale_value_1`, `scale_value_2` (snake) |

### 2-2. `DISTINCT_TASKS` — 개별 과제 선행 (합성, 12종)

서로 **다른 일**을 하는 12개 함수. "반복 데모 모방" 반론을 방어하기 위한 대조군.
예시 이름: `sumList`, `maxValue`, `reverseString`, `isEven` (camel) / `sum_list`, `max_value`, `reverse_string`, `is_even` (snake).

| # | 이름(단어) | 설명 |
|---|---|---|
| 1 | sum / list | returns the sum of a list |
| 2 | max / value | returns the largest value in a list |
| 3 | reverse / string | reverses a string |
| 4 | is / even | checks whether a number is even |
| 5 | to / upper | converts a string to upper case |
| 6 | first / item | returns the first item of a list |
| 7 | last / item | returns the last item of a list |
| 8 | square / number | returns the square of a number |
| 9 | join / words | joins a list of words with spaces |
| 10 | strip / spaces | strips leading and trailing spaces |
| 11 | double / value | returns the value doubled |
| 12 | abs / diff | returns the absolute difference of two numbers |

### 2-3. `NAME_PAIR_POOL` — 이름 짝 풀 (합성, 80종)

동사 20개 × 명사 20개를 shift(0~3)로 짝지어 **서로 다른 두 단어 이름 80개**를 결정적으로 생성.
**본문·매개변수는 전 항목 공통**(`return value`)이라 변수는 오직 이름 표기뿐.
어텐션 비교(stepB)와 KV 치환(stepC·step1·step2)에서 "같은 이름의 camel판/snake판"을 만들 때 쓴다.

| 항목 | 값 |
|---|---|
| 동사(20) | parse, build, fetch, render, encode, decode, expand, split, filter, format, resolve, compute, extract, validate, normalize, serialize, append, compress, flatten, collect |
| 명사(20) | header, payload, token, buffer, record, node, entry, config, session, request, packet, matrix, vector, index, cursor, stream, column, segment, handle, frame |
| 조합 | verb[i] × noun[i..i+3] (shift 0~3) = 20 × 4 = **80** |
| 본문 | `return value` (전 항목 공통) |
| 매개변수 | `value` |
| 예시 이름 | `parseHeader`, `buildPayload`, `fetchToken`, `encodeRecord` (camel) / `parse_header`, `build_payload`, `fetch_token`, `encode_record` (snake) |

> 생성 과제(remove/count/merge)의 단어와 겹치지 않도록 `merge`는 풀에서 제외(→ `expand`).

### 2-4. `GENERATION_TASKS` — 생성 대상 (합성, 3종)

모델이 **직접 이름을 지어 작성**하는 함수 3개. 측정 대상. 서로 다르고 선행과도 다르다.
첫 함수의 표기가 준수율, 2·3번째는 자기증폭 관측용.
기대 이름: `removeDuplicates`, `countVowels`, `mergeDicts` (camel) / `remove_duplicates`, `count_vowels`, `merge_dicts` (snake).

| # | 이름(단어) | 설명 | 본문 |
|---|---|---|---|
| 1 | remove / duplicates | removes duplicate items from a list, preserving order | `return list(dict.fromkeys(items))` |
| 2 | count / vowels | counts the vowels in a string | `return sum(c in "aeiou" for c in text.lower())` |
| 3 | merge / dicts | merges two dictionaries | `return {**a, **b}` |

> 원래 1번 과제는 `clamp`였으나 모델이 한 단어 `clamp`로 축약해 표기 판정 불가(`other`)가 되어,
> **두 단어가 강제되는** `remove duplicates`로 교체(stepA-1·stepA-2 결과 권고).

### 2-5. `data/repo_files/` — 실제 저장소 코드 (실코드, 6파일)

선행을 합성이 아니라 **진짜 소스 파일**로 바꾼다. 언어별 표기 관습(Python=snake, JS=camel)을
조작 없이 자연 실험으로 이용. 원문 그대로 번들(수정 없음). 출처·라이선스: `data/repo_files/SOURCE.md`.

| 파일 | 언어 | 관습 | 출처 | 실제 함수명 예시 |
|---|---|---|---|---|
| `python/fnmatch.py` | Python | snake | CPython `v3.11.0` (PSF) | `fnmatch`, `fnmatchcase`, `translate`, `_compile_pattern` |
| `python/textwrap.py` | Python | snake | CPython `v3.11.0` (PSF) | `_munge_whitespace`, `_fix_sentence_endings`, `_handle_long_word`, `dedent` |
| `python/string.py` | Python | snake | CPython `v3.11.0` (PSF) | `safe_substitute`, `get_field`, `format_field`, `capwords` |
| `javascript/utils.js` | JavaScript | camel | axios `v1.6.0` (MIT) | `forEach`, `findKey`, `merge`, `isBuffer` |
| `javascript/buildURL.js` | JavaScript | camel | axios `v1.6.0` (MIT) | `buildURL`, `encode` |
| `javascript/formDataToJSON.js` | JavaScript | camel | axios `v1.6.0` (MIT) | `formDataToJSON`, `arrayToObject`, `parsePropPath` |

> **참고.** Python stdlib 공개 API에는 한 단어 이름(`wrap`, `fill`, `translate`, `fnmatch`)이 흔하고,
> 한 단어는 하네스 판정상 camel/snake 아닌 **`other`**다. snake 관습은 두 단어 이상 이름
> (`safe_substitute`, `get_field`, `_munge_whitespace`)에서 드러난다. `fnmatch.py`는 특히 한 단어 이름이 많다.
> (다만 stepA-2 결과상 Python 파일은 fnmatch 포함 모두 snake 생성을 유도했다 — `docs/stepA-2/results.md`.)

## 3. step별 사용 데이터셋

생성 실험은 모두 **선행 코드 + `GENERATION_TASKS`(생성 3)** 구조다. 아래는 각 step이 쓴 **선행 코드**와,
그 step이 실제로 만든 **조건(=프롬프트) 수**다. 조건 하나 = `격자 1칸 × seed 1개`.

| step | RQ | 선행 데이터셋 | seed | 조건 수 (격자 × seed) |
|---|---|---|---|---|
| **step 0** | 전체 | — (하네스 골격) | — | 0 (데이터 없음) |
| **step A** | RQ1 | `CLONE_TASK` | 0–19 (20개) | 5(준수 4/3/2/1/0) × 20 = **100** |
| **step A-1** | RQ1 | `DISTINCT_TASKS` | 0–19 (20개) | 5(준수 4/3/2/1/0) × 20 = **100** |
| **step A-2** | RQ1 | `data/repo_files/` (실코드 6파일) | 0 (1개, 고정) | 6파일 × 2지침(camel/snake) = **12** |
| **step B** | RQ2 | `NAME_PAIR_POOL` (n=12) | 0–19 (20개) | 7spec(6/6 flip 2 + 위반스윕 5) × 20 = **140** |
| **step C** | RQ2 | `NAME_PAIR_POOL` (n=0) | 0–19 (20개) | 3donor × 20 = **60** |
| **step 1** | RQ2 | `NAME_PAIR_POOL` (n=0) | 0–9 (10개) | 스윕 2donor × 10 + 코사인 10 = **30** |
| **step 2** | RQ2 | `NAME_PAIR_POOL` (n=0) | 0–9 (10개) | step1 격자(30) × 모델 3 = **90** |
| **step 3** | RQ1 | `CLONE_TASK` | 0–19 (20개) | 4(준수) × 20 × 3그룹 = **240** (⚠ 폐기) |

- 각 조건은 프롬프트 1개(선행 + 생성 3턴)다. `n_compliant`가 격자축이면 **준수 개수**를, donor·spec이면 **개입/배치 종류**를 뜻한다.
- **seed 역할:** 표기 배치(POOL은 이름 집합까지)를 결정 — 같은 격자 칸이라도 seed마다 다른 이름 배열이 나온다.
- step A-2만 실코드라 seed 셔플이 없다(파일 원문 고정) → seed 1개.

**요약**

- RQ1(행동 절벽): stepA=CLONE, stepA-1=DISTINCT, stepA-2=실코드, step3=CLONE(snake headroom).
- RQ2(내부 신호): stepB·C·1·2는 모두 **`NAME_PAIR_POOL`(POOL)** 을 공유 — 같은 이름의 camel판/snake판 대응쌍이 필요하기 때문.
- 생성 대상은 전 step 공통 `GENERATION_TASKS`(remove/count/merge).

## 4. 다른 모델로 재현 (step2)

step2는 **새 데이터를 만들지 않는다.** stepA·B·C·1에서 Qwen으로 쓴 것과 **똑같은 합성 프롬프트·seed·측정 지표**를 다른 모델에 그대로 넣어, **RQ 논리가 모델 간에 유지되는지**만 본다. 절대 수치·반응 층은 모델마다 달라도 되고, 다음 논리 사슬이 성립하면 재현 성공이다.

| 단계 | Qwen에서 확인한 것 | 다른 모델서 볼 것 (수치·층 달라도 OK) |
|---|---|---|
| **stepA** | 준수 개수 ↓ → 준수율 **절벽** | 다른 모델도 절벽이 나오는가 |
| **stepB** | 이름 생성 시점에 **위반 표기를 더 봄**(Qwen=L25) | 어느 층에서든 위반 표기를 더 보는가 |
| **stepC** | 그 표현을 준수판으로 치환 → **회복** | 치환하면 준수 선호가 회복되는가 |
| **step1** | 신호가 **Value 경로·형태·소수 층 국소** | Value 우세·국소화가 유지되는가 |

**재현 범위:** 모델 간 재현은 **핵심 논리 사슬 A→B→C→1만** 돈다. **stepA-1·stepA-2는 제외** — 이 둘은 RQ1의 **데이터 외적 타당성 대조군**(데모 모방 방어 · 실코드)이라 *데이터* 다양성을 방어하는 실험이지, *모델* 일반화의 대상이 아니다.

**토크나이저 주의:** 개입 3단계(B·C·1)의 이름 풀은 camel판/snake판이 **토큰 정렬**되어야 KV 치환·v 비교가 성립한다. **모델마다 토크나이저가 다르므로**, step2에서는 **모델별로 이름 풀을 다시 걸러** 정렬 가능한 이름만 쓴다. (생성 단계 stepA는 정렬 무관.)
