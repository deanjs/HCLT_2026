# 코드 생성 모델의 표기 규약 준수 실패에 대한 Probing 연구 — 연구 계획서

**한정석 (CSE 202311398)**

---

## 0. 한 문장 요약

> 코드 생성 모델은 표기 규약을 **논리적 제약이 아니라 표층 형태 신호**로 처리한다.
> 이 원리는 선행 코드와 지침 문장 양쪽에서 동일하게 작동하며,
> 따라서 지침 구간 전체를 균질하게 증폭하는 기존 완화 기법은 실패한다.

이 문장을 세 조각으로 자른 것이 RQ1~RQ3이고, 세 조각에서 얻은 답이 그대로 제안 방법론의 설계 근거 세 개가 된다.

---

## 1. Introduction 구성

### 1.1 현행 문제점

코딩 에이전트에 `CLAUDE.md`, `AGENTS.md` 형태로 프로젝트 표기 규약을 지정해도, 세션이 진행될수록 모델은 그 규약을 점차 위반한다. 지침은 컨텍스트에 그대로 남아 있으므로 이것은 **지침이 사라지는 문제가 아니라 지침이 있는데도 따르지 않는 문제**다.

### 1.2 왜 이런 일이 발생하는가

생성된 코드가 컨텍스트에 누적되면서 초기 지침과 경쟁한다는 것이 출발 가설이다. 그러나 "경쟁한다"는 서술만으로는 무엇이 경쟁 신호인지, 그것이 모델 어디에 존재하는지, 그리고 그 신호를 어떻게 다뤄야 하는지를 알 수 없다. 그래서 세 개의 질문으로 나눈다.

### 1.3 Research Questions

| | 질문 | 층위 |
|---|---|---|
| **RQ1** | 선행 코드의 지침 위반은 이후 생성의 준수율을 낮추는가? | 행동 |
| **RQ2** | 그 실패를 매개하는 내부 신호는 코드의 **내용**인가 **표층 형태**인가, 그리고 어느 층에 존재하는가? | 기제 |
| **RQ3** | 동일한 표층 형태 원리가 **지침 구간**에도 적용되는가? | 일반화 |

세 질문은 독립적이지 않고 순차적이다.

```
RQ1: 붕괴가 실재하는가
      ↓ 그렇다면 무엇이 매개하는가
RQ2: 내용이 아니라 형태이며, 특정 층에 국소화된다
      ↓ 그렇다면 지침 쪽도 같은 방식으로 읽히는가
RQ3: 그렇다. 지침 구간은 균질하지 않다
      ↓ 세 답을 근거로
방법론: 형태 인식 선택적 스티어링
```

## 2. RQ별 현황과 남은 실험

### RQ1 — 선행 코드의 지침 위반은 이후 생성의 준수율을 낮추는가?

**설계.** 함수 12개짜리 선행 코드를 배치하고, 그중 규약을 지킨(camelCase) 함수 개수를 4/3/2/1/0으로 무작위 배정한다. 나머지는 기능이 동일한 snake_case 버전이며 위치는 섞는다. 이후 새 함수 3개를 순차 생성시키고 첫 함수의 표기를 측정한다.

**현재까지의 답 (A1).**

- 준수 예시가 하나라도 남아 있으면 준수율 85~90% 유지
- 0개가 되는 순간 30%로 하락 — 점진적 감소가 아니라 **절벽**
- 첫 함수가 위반하면 이후 함수도 연쇄 위반 — 모델 자신의 출력이 다시 입력으로 쌓이는 **자기증폭**

**남은 실험.** 현재 선행 코드는 12개 함수가 모두 같은 일을 하고 이름만 다르다. "이것은 지침 준수 실패가 아니라 in-context 데모 오버라이드다"라는 반론이 가능하며, 0개에서만 절벽이 생기는 패턴은 실제로 ICL 문헌의 예측과 일치한다. 이 반론을 막지 못하면 논문 전체가 무너진다. → **Step 3, Step 4**

---

### RQ2 — 매개 신호는 내용인가 형태인가, 어느 층에 있는가?

**설계.** 지침을 camelCase / snake_case 두 종류로 두고 2×2 표를 만들어, 어떤 지침이든 **현재 지침과 충돌하는 표기**를 더 참조하는지 확인한다. 이후 위반 상태의 선행 코드 요약값(Key/Value)을 준수 상태 값으로 치환해 준수 선호 점수가 회복되는지 본다.

**현재까지의 답 (A2).**

| 관측 | 결과 |
|---|---|
| 지침 참조 비율의 조건별 변화 | 평탄 — **기각**. 지침을 덜 보는 것이 아니다 |
| 충돌 표기 토큰 참조 | camel 지침일 때 snake를 더 봄 / snake 지침일 때 camel을 더 봄 |
| 전달 정보 크기 | 어텐션뿐 아니라 해당 토큰의 value 크기도 증가 |
| 선행 코드 KV 치환 (L25) | 준수 선호 **약 79% 회복** |
| 무관한 camel 코드 투입 | **동일하게 회복** → 내용이 아니라 표기 스타일이 신호 |
| 지침 어텐션 증폭 / 반감 | 증폭 시 준수 상승, 반감 시 준수 선호가 음수로 전환 |

지침 참조 비율이 평탄했다는 관측이 특히 중요하다. 이는 실패 모드가 **지침 결핍**이 아니라 **경쟁 신호의 증대**임을 뜻하며, 어텐션 결핍을 전제로 하는 기존 완화 기법과 직접 충돌한다.

**남은 실험.**

1. **L25는 왜 25층인가.** 단일 층을 찍은 결과만으로는 발견이라 부를 수 없다. 전 층을 스윕해 회복률 곡선을 그려야 한다. 이 곡선이 없으면 제안 방법론에서 "어느 층에 개입할 것인가"의 근거가 임의적으로 보인다. → **Step 1**
2. **모델마다 같은 층인가.** 모든 모델이 동일 층에서 반응할 필요는 없다. "모델마다 위치는 다르되 항상 특정 층에 국소화된다"가 나오면 그것이 A2의 알맹이다. → **Step 2**

### RQ3 — 같은 원리가 지침 구간에도 적용되는가?

**착안점.** 지침을 부정형으로 쓰면 지침 문장 자체가 위반 스타일 토큰을 포함하게 된다.

> `snake_case로 작성하지 마라` ← 이 문장은 지침 구간 안에 `snake_case`를 심는다.

모델이 부정을 논리 연산자로 처리한다면 이 지침은 `camelCase로 작성하라`와 등가여야 한다. 반대로 표층 형태로 처리한다면, **지침 문장이 스스로 위반 신호의 공급원**이 된다. RQ2에서 확인한 "충돌 표기 토큰을 더 본다"는 현상이 선행 코드가 아니라 지침 구간에서 일어나는 상황이다.

**조건 설계 (2×2×2).**

| 지침 문구 | 형식 | 목표 표기 | 지침에 등장하는 토큰 |
|---|---|---|---|
| camelCase로 작성하라 | 긍정 | camel | camel (= 준수 표기) |
| snake_case로 작성하지 마라 | 부정 | camel | **snake (= 위반 표기)** |
| snake_case로 작성하라 | 긍정 | snake | snake (= 준수 표기) |
| camelCase로 작성하지 마라 | 부정 | snake | **camel (= 위반 표기)** |

여기에 선행 코드 조건(camel prefix / snake prefix)을 교차한다. 이 설계는 **"지침에 어떤 표기 토큰이 들어 있는가"**와 **"어떤 표기가 요구되는가"**를 완전히 분리한다.

**예상되는 답 (A3).** 부정형 지침에서 준수율이 하락하고, 지침 구간 내 위반 표기 토큰에 대한 어텐션이 증가한다. 즉 지침 구간은 균질하게 유익하지 않다.

**설계 주의사항.**

- **닫힌 선택지 명시.** "snake_case로 작성하지 마라"는 논리적으로 camelCase를 함의하지 않는다(PascalCase 등이 열려 있다). 프롬프트에 표기 후보를 두 개로 못 박아야 긍정형과 논리적 등가가 성립한다. 준수 선호 점수는 고정 후보 2개를 채점하므로 이미 닫혀 있으나, 생성 실험에서는 명시가 필요하다.
- **지침 구간 토큰 수 보정.** 긍정형과 부정형은 길이가 다르다. 참조 비율 지표는 구간 토큰 수로 나누므로 영향이 없으나, 어텐션 구간 비율을 다루는 개입에서는 구간 크기가 직접 영향을 준다.
- **부정 유형은 명시적 부정 하나로 시작.** 참고 논문(Seo et al., 2025)도 본 실험은 명시적 부정으로 수행하고, 암시적·형태적 부정은 소규모 부분 치환 부록 실험으로 다뤘다. 동일 구성을 따른다. 여유가 생기면 `지양하라` 계열(암시적), `non-snake_case`(형태적)를 부록으로 추가한다.

→ **Step 5, Step 6**

## 3. 제안 방법론 — 형태 인식 선택적 스티어링

세 개의 답이 그대로 세 개의 설계 결정이 된다.

| 설계 결정 | 근거 |
|---|---|
| 추론 시점 개입이 필요하다 | **A1** — 준수 붕괴가 실재하고 자기증폭한다 |
| 전 층이 아니라 **특정 층에만** 적용한다 | **A2** — 매개 신호가 특정 층에 국소화되어 있다 |
| 지침 구간 전체가 아니라 **준수 표기 토큰만** 증폭한다 | **A3** — 지침 구간이 균질하지 않다 |

기존 어텐션 스티어링(Venkateswaran & Contractor, 2026)은 전 레이어·전 헤드에 지침 구간 전체를 균질하게 증폭한다. 제안 방법은 개입 지점을 두 방향으로 좁힌다: **층 방향**(RQ2의 스윕 결과로 선택)과 **구간 내부 방향**(준수 표기 토큰 vs 위반 표기 토큰 구분).

- 추가 학습·미세조정 불필요, 추론 시점 훅으로 구현
- 비교군: baseline / 균질 스티어링 / 제안 방법
- 평가: 긍정형 지침 조건과 부정형 지침 조건 양쪽에서 준수율 및 생성 품질

**이 배치의 의미.** 제안 방법은 기존 기법을 반박하는 것이 아니라 **적용 범위를 정밀화하는 개선**이다. 비판으로 끝나는 논문보다 안전하고, RQ에서 얻은 답 외의 추가 아이디어를 요구하지 않는다.

→ **Step 7**

## 4. 실행 계획

### Step 1. 층 스윕 — L25는 왜 25층인가 *(최우선)*

전 층에 대해 선행 코드 KV 치환을 반복하고 층별 준수 선호 회복률 곡선을 그린다. Qwen2.5-Coder-3B 기준. 무관 코드 통제 조건을 모든 층에서 함께 측정해 "내용이 아니라 형태" 결론이 층 전체에서 유지되는지 확인한다.

- 산출: 층별 회복률 곡선, 피크 층, 회복이 국소적인지 광범위한지
- 이 산출물이 Step 7의 층 선택 근거가 된다

### Step 2. 모델 다양성 — 다른 패밀리 2~3개 *(최우선)*

Qwen 3B/7B는 학습 데이터와 토크나이저가 같아 "다른 모델"이 아니다. **패밀리가 다른 코드 특화 instruct 모델 2~3개**에서 Step 1을 반복한다. 크기는 클 필요 없다.

- 확인할 것: 피크 층 위치가 모델마다 다른가 / 국소화 자체는 공통인가
- 주의: T4 메모리 제약으로 양자화가 필요할 경우, 양자화가 KV 치환의 수치 정밀도에 영향을 주는지 먼저 검증한다. 정밀도 손실이 확인되면 fp16으로 올릴 수 있는 크기의 모델을 우선한다

### Step 3. 선행 코드 구성 ablation *(RQ1 방어)*

동일 작업 12개 클론 vs 서로 다른 작업 12개 함수로 선행 코드를 바꿔 절벽 효과를 재측정한다. 후자에서도 절벽이 재현되면 "in-context 데모 오버라이드" 반론이 무력화된다.

### Step 4. 실제 저장소 코드 재현 *(RQ1 외적 타당성)*

합성 코드가 아닌 실제 저장소 파일을 선행 코드로 사용한다. 언어별 관습 차이가 자연 실험 역할을 한다.

| | 지침 = camelCase | 지침 = snake_case |
|---|---|---|
| **Python 파일** (PEP8 → 자연 snake) | 충돌 | 일치 |
| **JS/Java 파일** (자연 camel) | 일치 | 충돌 |

실제 코드를 조작하지 않고 지침만 무작위 배정해 2×2가 완성된다. 여기서는 생성률만 측정하며 내부 개입은 하지 않는다(대응쌍 구성이 불가능하므로). 여유가 있으면 Step 1의 피크 층에서 KV만 치환해 실제 생성률이 오르는지 확인한다.

### Step 5. 부정형 지침 행동 실험 *(RQ3 핵심)*

2절의 2×2×2 조건으로 준수율을 측정한다. **3B와 7B를 반드시 병행한다** — 3B가 부정형 지침 자체를 처리하지 못해 바닥 효과가 나는 경우, 그것을 표층 처리의 증거로 오독하면 논문이 통째로 무너진다. 7B에서도 같은 패턴이 나와야 능력 부족이 아니라 처리 방식의 문제라고 말할 수 있다.

### Step 6. 부정형 지침 내부 관측 *(RQ3 핵심)*

부정형 조건에서 지침 구간 내부의 토큰별 어텐션을 분해한다. 위반 표기 토큰과 나머지 지침 토큰을 나눠 측정해, 지침 구간이 균질하지 않음을 직접 보인다. Step 1의 층 스윕도 부정형 조건에서 반복해 피크 층이 이동하는지 확인한다.

### Step 7. 방법론 구현 및 평가

Step 1·2에서 얻은 층 정보와 Step 5·6에서 얻은 구간 정보를 결합해 형태 인식 선택적 스티어링을 구현한다. baseline / 균질 스티어링 / 제안 방법을 긍정형·부정형 양쪽 조건에서 비교한다.

### Step 8. 로짓 렌즈 층별 궤적 *(선택)*

층별로 준수 표기와 위반 표기의 확률 분포 차이를 추적한다. Step 1의 회복률 피크가 왜 그 층인지에 대한 해석을 제공한다. 참고 논문(Seo et al., 2025)의 주 분석 도구와 동일하다.

### Step 9. 관련 연구 및 공개 데이터셋 조사 *(논문 집필 병행)*

- 어텐션 스티어링, 지침 준수, 코드 스타일 일관성 관련 선행 연구 조사. 유사 연구가 있어도 무방하며, 오히려 위치 설정에 도움이 된다
