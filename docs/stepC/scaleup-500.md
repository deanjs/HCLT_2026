# step C — pool-500 (RQ2 인과, KV 치환, 500 이름 커버)

> 파일럿(`docs/stepC/plan.md`, 3 donor × seed 20, 80풀 랜덤 표집)의 **확대 재실행**이다.
> 개입·측정 로직은 그대로, 이름을 **블록으로 500+개 커버**한다. 공유 POOL 코드는 `stepB/pool-500`에서 물려받는다.
> 파일럿 결과는 `results/`에 불변 보존(§6).

---

## 1. RQ2 — 무엇이 궁금한가

**대응: RQ2 (인과).** 형태 신호가 표기 결정의 **원인**인가. (관측은 stepB)

**무엇이 궁금한가:** 텍스트는 그대로 두고(`format_matrix` 같은 위반 이름이 화면엔 그대로), 그 위반 이름이 **후반 층(L25)에서 갖는 내부표현(Value)만 준수판으로 바꿔치기**했을 때 준수 선호가 회복되는가. 회복되면 그 L25 형태 신호가 **원인**이다(관측→인과).

---

## 2. 어떤 실험을 하는가

개입·측정은 파일럿과 **동일**. 바뀌는 건 이름 선택뿐(블록).

### 개입 (KV 치환)
- **대상:** 선행의 위반 이름 토큰이 **L25**에서 갖는 Key/Value.
- **치환:** 같은 이름의 **준수 표기판이 L25에서 가졌을 값**(반사실 donor)으로 덮어쓴다. GQA라 **KV group 단위**.
- 텍스트 불변, 내부 표현만 수술.

### 세 상태의 준수 선호 점수 `S = logP(준수 후보) − logP(위반 후보)`
| 상태 | 선행 | 기대 S |
|---|---|---|
| **clean** | 위반 없음 | 높음(천장) |
| **baseline** | 위반 포함 | 낮음(실패) |
| **intervened** | 위반이지만 L25만 준수로 치환 | ? |

**회복률 = (S_int − S_base) / (S_clean − S_base).** 위반으로 떨어진 점수를 clean까지 얼마나 되돌렸나.

### donor 3종
| donor | 뜻 | 역할 |
|---|---|---|
| `compliant` | 같은 이름 준수판 | **주효과** |
| `unrelated_camel` | 무관한 준수형 이름 | **형태 통제** — 이것도 회복하면 신호는 *의미*가 아니라 **표기 형태** |
| `unrelated_snake` | 무관한 위반형 이름 | **음성 통제** — 회복 안 됨 기대 |

### 결과 해석 (어느 쪽이든 그대로 기록, §4)
| 관측 | 뜻 |
|---|---|
| `compliant` 치환 → 회복 | L25 형태 신호가 표기 결정의 **원인** (관측→인과) |
| `unrelated_camel`도 회복 | 신호는 이름의 *의미*가 아니라 **표기 형태** |
| `unrelated_snake` 회복 안 됨 | 준수 *형태* 값이라야 회복 — 아무 치환이 아님 |

## 3. 쓰는 데이터셋

| 항목 | 값 |
|---|---|
| 데이터 종류 | **합성(SYNTHETIC)** |
| 선행 구성 | `POOL`, **전부 위반**(n_compliant=0), 12함수 |
| 이름 풀 | `NAME_PAIR_POOL` — 50×50 → **504개** (`stepB/pool-500` 공유 코드) |
| 이름 선택 | **블록 커버리지** — 42블록이 500+ 위반 이름을 개입 대상으로 덮음 (`pool_block`) |
| 개입 | KV 치환, **L25**, donor 3종 |
| 시드 | **1** (블록이 다양성 제공; 위치·donor 강건성 원하면 3) |
| 조건 | 3 donor × 42 block × 1 seed = **126조건** (§3 "stepC 126조건"과 일치) |

> **500의 정의:** 서로 다른 위반 이름 수(504). 블록이 이를 개입 대상으로 덮고, seed는 자리·무관 donor 선택만 변주.

---

## 4. 데이터를 어떻게 구성했는가

### 블록 커버리지 (seed = 위치·donor 변주)
- 조건 하나 = **donor + 블록 b + seed**. 블록 b는 위반 이름 12개(`[b*12, (b+1)*12)`)를 개입 대상으로 삼는다.
- 42블록이 504개를 **중복 없이** 덮는다 → 500+ 위반 이름 전부 개입.
- seed는 이름 12개의 **자리 순서**와 `unrelated_*` donor로 쓸 **무관 이름 선택**(블록 밖)만 섞는다.

### seed가 1로 충분한 이유
파일럿은 seed가 "어떤 위반 이름을 개입 대상으로 뽑나"를 정해 20개가 필요했다. 지금은 **블록이 500개 이름을 전부** 개입 대상으로 삼으므로, 주 결과(형태가 원인·이름 무관)는 seed 1로 이미 확보된다. seed는 위치·donor 강건성용 부차 축(§3 stepC 3 권장).

### 통제 유지
선행 함수 본문·매개변수는 전 항목 공통(`return value`) — 변하는 것은 이름 표기뿐. 개입은 텍스트를 건드리지 않고 L25 KV만 치환.

---

## 5. 재현성 (POOL이라 stepA와 다름)

POOL은 이름을 풀에서 뽑고, 풀 크기·선택 방식이 바뀌었으므로 파일럿 stepC는 **글자 그대로 재현되지 않는다**(승인: 새 500 샘플). 파일럿은 `results/stepC/` 불변 보존(§6), scaleup은 **500개 위반 이름 일반화 실행**을 `results/stepC_scaleup500/`에 새로 쌓는다. 원래 이름 80개는 새 풀의 부분집합으로 남아 연속성 유지.
