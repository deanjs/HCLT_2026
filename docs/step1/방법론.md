## 1. 왜 이 실험을 하나

논문의 **문제 제기**다. "코드 LLM이 표기 규약 지침을 어긴다"는 현상이 실재하는지,
어떤 조건에서 무너지는지를 먼저 보여야 나머지 스텝(왜 그런가)이 의미를 갖는다.

**RQ1 — 문맥의 규약 위반이 준수율을 떨어뜨리나?**

이 스텝만 **실제로 생성시킨다.** 나머지는 전부 확률 채점(교사강제)이다.

---

## 2. 무엇을 조작하나

앞선 코드 12개 함수 중 **규약을 지킨 개수**를 0~12로 바꾼다. 그것뿐이다.

```
[system]  In this project we generally write function names in camelCase.
          Every function name uses one of two styles only: camelCase or snake_case.

[user]    Here is the current module:
          ```python
          def splitConfig(value): ...      ← 준수 (camel)
          def merge_data(items): ...       ← 위반 (snake)
          def scaleValue(x): ...           ← 준수
          ... 12개, 준수/위반 비율이 조건 ...
          ```
          Add a function that removes duplicate items from a list, preserving order.

[모델]    def ???
```

모델이 쓴 **첫 함수 이름의 표기**를 센다.

| 축 | 값 |
|---|---|
| 준수 개수 | 0, 1, 2, …, 12 (13수준) |
| 지침 목표 | camelCase / snake_case |
| 이름 묶음 | 42개 (504개 이름을 12개씩) |
| 모델 | Qwen2.5-Coder-3B · StableCode-3B |

**2 × 13 × 2 × 42 = 2184조건.**

## 2-1. 실제로 만들어지는 프롬프트

위 그림은 뼈대만 보인 것이다. **실제로 모델에 들어가는 글자 전체**는 아래와 같다
(`prompt.py:241 initial_messages`가 만든 것을 그대로 찍었다. 재현: §2-3).
step1은 **프롬프트가 하나뿐이다** — 개입이 없으니 공여도 천장 기준도 없다.

```
[system] You are helping extend an existing Python module.
         In this project we generally write function names in camelCase.
         Every function name uses one of two styles only: camelCase or snake_case.
[user]   Here is the current module:

         ```python
         def split_config(value):      ← 위반(snake)
             return value
         def decodeNode(value):        ← 준수(camel)
             return value
         def fetchToken(value): ...    ← 준수
         def filter_session(value): ...    ← 위반
         def format_request(value): ...    ← 위반
         def expand_entry(value): ...      ← 위반
         def compute_matrix(value): ...    ← 위반
         def renderBuffer(value): ...      ← 준수
         def encodeRecord(value): ...      ← 준수
         def parseHeader(value): ...       ← 준수
         def buildPayload(value): ...      ← 준수
         def resolve_packet(value): ...    ← 위반
         ```

         Add a function that removes duplicate items from a list, preserving order.
```

**조건이 바꾸는 것은 이 12줄 중 camel로 쓴 개수 하나뿐이다.** 위 예는 준수 6개
(`n_compliant=6`). 0이면 12개가 전부 snake, 12면 전부 camel이다. 지침 문장·과제 문장·
함수 몸통(`return value`)은 13수준 내내 **글자 하나 안 바뀐다.**

> **주의.** 한 묶음 안에서 camel로 쓴 함수와 snake로 쓴 함수는 **서로 다른 이름**이다
> (`split_config`가 camel판이 되는 게 아니라, 다른 이름 `decodeNode`가 camel 자리를 맡는다).
> 어휘 수준에서 균형만 맞춘 별개 집합이다 — §3의 경고와 같은 이야기다.

## 2-2. 측정 절차

step3·step5와 달리 **점수를 재지 않는다. 진짜로 생성시키고 나온 이름을 본다.**

```
   1. 위 프롬프트를 모델에 넣고 실제로 생성시킨다
        그리디(temperature=0) · 시드 42 · 최대 256토큰   (model.py:61 chat_generate)

   2. 생성문에서 **첫 번째** `def <이름>(` 을 정규식으로 뽑는다   (naming.py:52)
        _DEF_RE = r"\bdef\s+([A-Za-z_][A-Za-z0-9_]*)\s*\("

   3. 그 이름을 camel / snake / other 로 분류한다   (naming.py:40)
        camel : ^[a-z][a-z0-9]*(?:[A-Z][a-z0-9]*)+$     예 removeDuplicates
        snake : ^[a-z][a-z0-9]*(?:_[a-z0-9]+)+$         예 remove_duplicates
        other : 둘 다 아님 (예 RemoveDuplicates, 한 단어 이름)

   4. 분류 == 지침 목표 표기인가?  →  준수 1 / 아니면 0
        결과 파일의 extra.first_compliant

   5. 같은 조건을 42묶음에 대해 반복 → 준수율 = 42개의 평균
```

**실제로 나온 것**(위 프롬프트, Qwen 실측):

```
 생성문:  "To add a function that removes duplicate items ... Here's how you can
           implement this:

           ```python
           def remove_duplicates_preserve_order(input_list):
               seen = set()
               ...
           ```"

 뽑은 이름:  remove_duplicates_preserve_order
 분류:       snake
 지침 목표:  camel
 → first_compliant = false,  이 조건의 값은 0
```

> **조건마다 생성은 한 번뿐이다.** 그리디라 같은 조건을 다시 돌려도 같은 글자가 나온다.
> 흔들림은 시드가 아니라 **42묶음(다른 이름들)** 에서 온다. 그래서 신뢰구간이
> "이름을 바꾸면 얼마나 달라지나"를 뜻한다.

**조건 수 계산.** 지침 2방향 × 준수 개수 13수준 × 42묶음 × 모델 2개 = **2184개**.

## 3. 데이터셋

동사 50개 × 명사 50개로 만든 **함수 이름 504개**. 12개씩 42묶음으로 나눠 전체를 덮는다.

```
render_camel(["split","config"])  →  splitConfig
render_snake(["split","config"])  →  split_config
```

- 두 표기가 **같은 단어에서** 나오므로 의미는 같고 표기만 다르다
- 생성 과제 단어(`remove`/`duplicates` 등)와 겹치지 않게 만들었다 — 베끼기 혼입 방지

> **주의(문서에 반드시 적을 것):** 한 묶음 안에서 camel 진영과 snake 진영은 **서로 다른 이름**이다.
> "같은 이름을 표기만 바꿔 비교"가 아니라 **어휘 수준에서 균형을 맞춘 별개 집합**이다.
> 그리고 이 배정은 **시드를 바꿔도 변하지 않는다**(아래 §7).

## 6. 결과 요약

| 지침 목표 | 결과 |
|---|---|
| **camelCase** | 위반 5개 이상에서 준수율이 **정확히 0.000** |
| **snake_case** | 위반이 12개여도 준수율 0.88~1.00 — **천장 효과, 판정 불가** |

파이썬에서 snake는 모델의 기본값이라 지침과 사전 선호가 같으면 문맥이 힘을 못 쓴다.
**RQ1은 "지침이 모델의 사전 선호와 어긋날 때" 조건부로 성립한다.**

## 7. 처음과 달라진 것

| # | 처음 | 지금 | 왜 |
|---|---|---|---|
| **개념** | "같은 이름을 표기만 바꿔 비교" | "**어휘 수준 균형을 맞춘 별개 집합**" | 한 묶음 안에서 camel/snake 진영이 서로 다른 이름이다. 42블록 전수 확인: 정규화 후 겹치는 어휘 **0개** |
| **개념** | 시드가 표기 배정을 섞는다 | **시드는 표기 배정을 못 바꾼다** | `_pool_indices`와 `notations`에 **같은 시드로 같은 셔플**을 걸어, 풀의 몇 번째 이름이 camel이 되는지가 고정된다. seed 42/7/123/999에서 camel 이름 252개 집합이 **동일** |
| **개념** | "절벽" | "**위반 5개 임계의 계단**" | 위반 4개까지는 부분적으로 버티고, 5개부터 **정확히 0**으로 떨어져 회복하지 않는다 |
| **분석** | 양 방향을 함께 보고 | **snake 방향은 천장 효과로 판정 불가** 분리 | 조작이 통하지 않는 조건은 근거가 될 수 없다 |
| **측정** | 자기증폭(뒤 함수도 위반하나) | **측정된 적 없음 — 주장에서 제외** | 결과 2184개 전부 `turn_notations` 길이가 **1**이다. 뒤따르는 함수가 아예 없어 재계산이 불가능하다 |
| **코드** | `subsequent_violation_rate` 주석은 "첫 함수가 위반일 때" | 구현은 **무조건부** | 주석↔구현 불일치. 다시 돌린다면 집계 방식을 먼저 정해야 한다 |
| **커버리지** | 4모델 | **2모델(코드 특화)** | 연구자 판단으로 범위 확정 |
| **범위** | 파이썬 + 자바스크립트 | **파이썬만** | JS 조건은 실행된 적이 없다(결과 2184개 전부 `lang=null`) |

> `PrecedingCode.lang` 필드는 남겨 둔다 — 지우면 기존 결과 2184개를 못 읽는다.
