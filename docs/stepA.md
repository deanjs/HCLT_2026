# step A — RQ1 절벽 재현 (A1 생성)

**한 줄:** 선행 코드에 규약 준수 예시가 몇 개 남았느냐에 따라 이후 생성의 준수율이 어떻게 변하는지 재서, "0개에서 절벽 + 자기증폭"을 이 하네스에서 직접 만든다.

대응: **RQ1** (선행 코드의 위반이 이후 준수율을 낮추는가) — 계획서 §3 RQ1.

## 프롬프트 구조: 선행 12 + 생성 3

| 구획 | 개수 | 기능 | 표기 | 역할 |
|---|---|---|---|---|
| **선행** | 12 | 조건에 따라 다름(아래) | `n_compliant`개 camel + 나머지 snake, 위치 셔플 | 모델이 읽는 재료 |
| **생성** | 3 | **서로 다름**(distinct) | 모델이 선택 | 측정 대상 |

- **선행 12**는 프롬프트에 미리 써넣는 함수(모델은 읽기만).
- **생성 3**은 모델이 새로 쓰는 함수. **첫 번째**의 표기가 준수율, 2·3번째는 자기증폭 관측용.
- 생성 3은 선행 과제와도, 서로와도 달라야 한다 — 같으면 모델이 이름을 복사해 "직접 선택"을 못 본다.

## 바꾸는 조건 축

| 축 | 값 |
|---|---|
| 선행 `n_compliant` | **4 / 3 / 2 / 1 / 0** (12개 중 camel 준수 개수) |
| 선행 `composition` | **clone 과 distinct 둘 다** (비교) |
| 선행 `source` | synthetic |
| 지침 | 긍정 · 목표=camel · 약한 어조 |
| 개입 | none |
| 반복 | 조건당 seed 20 |

→ 5(개수) × 2(구성) × 20(seed) = **200회 생성**.

### clone vs distinct (이번 step의 핵심 비교)

| 구성 | 선행 12개의 기능 | 무엇을 방어하나 |
|---|---|---|
| **clone** | 모두 동일, 이름만 다름 | A1 기본 재현 |
| **distinct** | 12개가 서로 다른 과제 | "그냥 데모 따라한 것(ICL 오버라이드)" 반론 |

원래 distinct는 step 3였으나, 절벽이 두 구성에서 어떻게 다른지 **바로 옆에서 비교**하려고 step A에서 함께 돌린다.

## 재는 것

- **준수율**: 생성 첫 함수가 camel인가 (조건별 비율)
- **자기증폭**: 첫 함수 위반 시 2·3번째로 위반이 연쇄되는가

## 예상과 해석 (어느 쪽이든 그대로 기록, §4)

| 결과 | 해석 | 다음으로 |
|---|---|---|
| ≥1개는 85~90%, **0개에서 ~30% 급락** | 절벽 재현 = A1 | RQ2("무엇이 매개하나") |
| 4→0 매끄러운 하락 | 절벽 아님 | ICL 오버라이드와 구별 필요 |
| 첫 함수 위반 → 뒤 연쇄 | 자기증폭 확인 | 자기 출력이 다시 입력 |
| **clone에서만 절벽, distinct에선 없음** | 데모 효과 의심 | 반론 유효 → 프레이밍 축소 |
| **distinct에서도 절벽 재현** | 준수 실패가 데모 효과가 아님 | 반론 무력화 → RQ1 견고 |

## 구현 범위

`runner.py`의 생성 경로 4단계만 채운다:

| 단계 | 하는 일 |
|---|---|
| `build_preceding` | 선행 12개 구성 (clone/distinct, n_compliant camel + 나머지 snake, 셔플) |
| `build_instruction` | 지침 문장 (긍정·camel·약한 어조·닫힌 후보) |
| `build_prompt` | 선행 + 지침 + 생성 과제 → 프롬프트 조립 (chat template) |
| `measure_generation` | 3개 순차 생성 → 첫 함수 표기 판정 → 준수율·자기증폭 |

개입·어텐션 단계(step B·C)는 건드리지 않는다.

## 설정

- **모델**: `Qwen/Qwen2.5-Coder-3B-Instruct` (생성이라 fp16, T4 무료 티어 가능)
- **표기 판정**: 생성된 첫 `def`의 함수명이 camel/snake 중 무엇인지 정규식. 둘 다 아니면 `other`로 분류(준수·위반 어느 쪽도 아님)
- **과제 스펙**: 선행용 clone 과제 1 + distinct용 과제 12 + 생성용 과제 3을 합성으로 정의(코드에 고정)
