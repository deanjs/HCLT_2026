# step 1 — pool-500 (RQ2 층 스윕 + K/V 분해 + v 코사인, 500 이름 커버)

> 파일럿(`docs/step1/plan.md`, 2 donor × seed 10 + 코사인 10, 80풀 랜덤 표집)의 **확대 재실행**이다.
> 개입·측정 로직은 그대로, 이름을 **블록으로 500+개 커버**한다. 공유 POOL 코드는 `stepB/pool-500`에서 상속.
> 파일럿 결과는 `results/`에 불변 보존(§6).

---

## 1. RQ2 — 무엇이 궁금한가

**대응: RQ2.** 형태 신호가 **어느 층**에서, **어느 경로(Key/Value)** 로 작동하는가. (단일 층 인과는 stepC)

**무엇이 궁금한가:** stepC는 L25 한 층에서만 회복을 봤다. step1은 그 개입을 **전 층에 반복**하고 **Key/Value 경로를 분해**해 — (1) 회복이 어느 층에서 피크인지, (2) 신호가 어텐션(Key)인지 Value인지 — 를 가른다. 이게 방법론(step5 Value 경로 스티어링)의 **층·경로 선택 근거**가 된다.

---

## 2. 어떤 실험을 하는가

개입·측정 로직은 파일럿과 **동일**. 바뀌는 건 이름 선택뿐(블록). **두 갈래.**

### A. 개입 측 — 전 층 × K/V 분해 (인과)
- **바꾸는 것:** 위반 선행(POOL n=0)의 KV를 층을 0→L−1 돌며 준수판으로 치환. 각 층 세 경로: **Key만 / Value만 / Key+Value**. (KV group 단위, GQA)
- **재는 것:** 세 상태 `S`와 **회복률 = (S_int − S_base)/(S_clean − S_base)** 를 **모든 (층 × kind)** 에서.
- **donor 2종:** `compliant`(주효과) / `unrelated_camel`(형태 통제). 두 곡선이 전 층에서 겹치면 "내용 아니라 형태" 결론이 L25만이 아니라 전 층에서 유지됨. (음성통제 `unrelated_snake`는 stepC에서 회복률 0 확인 → 생략)

### B. 관측 측 — v 코사인 궤적 (방향)
- **재는 것:** 같은 이름의 **camel판 v와 snake판 v의 층별 코사인**. `‖v‖`(크기)는 안 변해도(배율 1.002) **방향**이 갈리는지.
- **왜:** 크기 지표는 방향을 지운다. 코사인만이 "크기 같아도 다른 정보를 싣는가"를 답한다.

### 결과 해석 (어느 쪽이든 그대로 기록, §4)
| 관측 | 뜻 | 다음 |
|---|---|---|
| 회복률이 특정 층에서 **피크** | 표기 결정이 그 단계에서 굳음 | step6 로짓 렌즈 |
| **Value만**으로 회복 | 형태 신호가 **Value 경로** | step5 개입을 Value로 |
| **Key만**으로 회복 | 어텐션(Key) 경로 | step5를 Key로 |
| v 코사인 **낮은 층 = Value 회복 피크 층** | 축 B(Value·방향) **확정** | Value 경로 확정 |

## 3. 쓰는 데이터셋

| 항목 | 값 |
|---|---|
| 데이터 종류 | **합성(SYNTHETIC)** |
| 선행 구성 | `POOL`, **전부 위반**(n_compliant=0), 12함수 |
| 이름 풀 | `NAME_PAIR_POOL` — 50×50 → **504개** (`stepB/pool-500` 공유) |
| 이름 선택 | **블록 커버리지** — 42블록이 500+ 위반 이름 커버 (`pool_block`) |
| 트랙 A 개입 | KV 치환, **전 층 스윕**, kind {key/value/key_value}, donor {compliant, unrelated_camel} |
| 트랙 B 관측 | v 코사인 (mode=vcosine) |
| 시드 | **1** (step1은 무거워 §3이 1~2 권장) |
| 조건 | 스윕 2 donor × 42 block = **84** + 코사인 42 = **총 126** (§3 "step1 42~84조건") |

> **500의 정의:** 서로 다른 위반 이름 수(504). 블록이 개입·관측 대상으로 덮고, seed는 자리·무관 donor 선택만 변주.

## 4. 데이터를 어떻게 구성했는가

### 블록 커버리지 (seed = 위치·donor 변주)
- 조건 하나 = **(donor, 블록 b) [스윕]** 또는 **(블록 b) [코사인]**. 블록 b는 위반 이름 12개를 대상으로 삼는다.
- 42블록이 504개를 **중복 없이** 덮는다 → 500+ 위반 이름 전부 개입·관측.
- seed는 이름 자리 순서와 `unrelated_camel` 무관 이름 선택(블록 밖)만 변주.

### seed=1로 충분한 이유
파일럿은 seed가 개입 대상 이름을 뽑아 10개가 필요했다. 지금은 **블록이 500개를 전부** 대상으로 삼으므로 주 결과(피크 층·경로가 이름 무관)는 seed 1로 확보된다. step1은 **전 층 × 3경로 개입이라 무거워** §3이 애초에 seed 1~2를 권장했다.

### 통제 유지
선행 본문·매개변수 공통(`return value`), 변하는 건 이름 표기뿐. 개입은 텍스트 불변, KV만 치환.

## 5. 재현성 (POOL이라 stepA와 다름)

POOL은 이름을 풀에서 뽑고 풀 크기·선택 방식이 바뀌었으므로 파일럿 step1은 **글자 그대로 재현되지 않는다**(승인: 새 500 샘플). 파일럿은 `results/step1/` 불변 보존(§6), scaleup은 **500개 위반 이름 일반화 실행**을 `results/step1_scaleup500/`에 새로 쌓는다. 원래 이름 80개는 부분집합으로 남아 연속성 유지.

> **주의(무료 T4):** 스윕은 조건 하나가 전 층(36)×3경로 개입이라 무겁다. 84 스윕조건이면 시간이 꽤 걸린다(재개 가능). 무료 티어면 `BLOCKS`를 줄여(예: `range(0,42,2)`) 21블록으로 반감.
